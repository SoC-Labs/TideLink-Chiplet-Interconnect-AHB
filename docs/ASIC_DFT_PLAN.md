## Preface — how to read this document

The TideLink v1 RTL was originally generated by the Wavious chiplet-controller
flow (Chisel → Verilog) and was hand-extended at SoC Labs for the GPIO-PHY
parallel-link variant. The Wavious flow emitted **DFT hook ports** at every
module boundary — `scan_mode`, `scan_clk`, `scan_asyncrst_ctrl`, `io_scan_in`,
`io_scan_out` — and **scan-aware mux structures** in the clock and reset
generators (`WavResetSync`, `WavClockGate`, `WavClockMux`). What it did **not**
emit is a TAP controller, scan stitching, MBIST controller, or boundary-scan
chain — those are tapeout-specific and were intentionally left for the
implementing team.

In the FPGA bring-up flow these scan ports are wired through the whole
hierarchy and tied to `1'b0` at the chip top (`src/rtl/tidelink_top.sv:1062`
and `:1592` — `.scan_mode(scan_mode)` from a top-level port that has no
driver). For ASIC tapeout we must instead wire those ports to a real TAP
controller, stitch all flops into scan chains, hook the SRAMs into an MBIST
controller, and surround the I/O ring with a 1149.1-compliant boundary-scan
register.

This document plans those additions at a scope-and-decisions level. Every
section that names a specific number (chain count, IDCODE field, etc.) is
marked **(TBD — DFT lead to confirm)** if not yet decided.

## 1. Goals + non-goals

### 1.1 Goals (v1 — must-have for tapeout)

* **Stuck-at ATPG ≥ 95 %** combinational coverage on the digital core
  (Wlink + axi-chiplet-controller + TideLink wrappers + XHB500 bridges +
  PHC + FC subsystem). This is the minimum threshold for foundry-grade
  defect screening at 65 nm.
* **MBIST on every SRAM** in the design — RX FIFO (16 KB compiled
  `rf_16k`, `src/rtl/asic/tidelink_sram.sv:48`) plus all Wlink internal
  packet/credit FIFOs. Algorithm coverage: March-C+ as the baseline,
  with the option to add March-LR for tapeout-2 if defect-screening
  yield demands it.
* **IEEE 1149.1-2013 compliant boundary scan** covering every primary
  I/O on the chiplet die: 8× pad_tx, 8× pad_rx (or 4×/4× — see §1.4 —
  the lane count is **NUM_PHY_LANES = 8** in production —
  `src/rtl/tidelink_top.sv:51`), pad_clk_tx, pad_clk_rx,
  TCK/TMS/TDI/TDO/nTRST, APB, AHB sub/tx/fifo/mng buses, PHC, POR,
  PMU sideband.
* **JTAG-driven scan and MBIST**: ATPG vectors and MBIST start/result
  must both be controllable and observable from the same 5-wire JTAG
  interface. No dedicated test pins beyond JTAG and `por_n`.
* **TAP in the always-on (AON) island** — so that post-power-gate
  test access still works during silicon bring-up (very useful for
  diagnosing power-domain failures).

### 1.2 Non-goals (deferred — not blocking tapeout)

* **At-speed (transition-fault) test as a sign-off gate.** We will
  insert the structures (LOC/LOS launch via scan-enable pulse) but
  achieving ≥ 80 % transition coverage is a tapeout-2 target. v1 will
  run TF ATPG and report whatever is achieved without making it a
  silicon-rejection gate.
* **Path-delay test.** Not in scope for v1 — would require carefully
  selected critical paths, and we have no timing-margin budget yet for
  guard-banding at-speed coverage.
* **Logic-BIST (LBIST).** Out of scope; deterministic scan ATPG is
  sufficient for the gate count.
* **MUX-based BIST patterns / programmable BIST.** The vendor-supplied
  `rf_16k` BIST controller will be used as-is. No bespoke BIST patterns.
* **In-system test (IST) / customer-mode self-test.** Not in scope. The
  chiplet is a test/research vehicle; no field-test mode required.
* **Power-aware ATPG.** v1 has no power gating in the digital core
  (only the AON island vs main is split). Power-aware vectors deferred
  to v2.

### 1.3 Coverage rates promised

| Fault model      | Target  | Hard-floor (sign-off) | Comment |
|------------------|---------|-----------------------|---------|
| Stuck-at         | 97 %    | 95 %                  | Hard sign-off gate |
| Transition fault | 85 %    | 80 % (report-only)    | Not a sign-off gate v1 |
| Bridging         | 92 %    | 90 % (report-only)    | Cell-aware (`-bridge`) |
| Cell-internal    | 80 %    | 75 % (report-only)    | TSMC65 cell-aware required |
| MBIST (memories) | 100 %   | 100 %                 | March-C+ |

### 1.4 Lane-count assumption

The plan below assumes the production 8-lane configuration
(`NUM_PHY_LANES = 8`, `src/rtl/tidelink_top.sv:51`). If the production
config drops to 4 lanes (it has historically toggled — see
`docs/GPIO_PHY_ARCHITECTURE.md` lane-table) the boundary-scan and pad
counts drop accordingly but the per-domain chain counts stay the same.

## 2. JTAG TAP controller (IEEE 1149.1)

### 2.1 Standard instructions (mandatory)

| Opcode (TBD) | Mnemonic       | DR length | Notes |
|-------------|----------------|-----------|-------|
| `0000`      | `EXTEST`       | BSR len   | Drive pads from BSR — interconnect test |
| `0001`      | `SAMPLE`       | BSR len   | Sample pad state, no drive — non-disruptive |
| `0010`      | `PRELOAD`      | BSR len   | Same as SAMPLE in the same shift — load pad values for next EXTEST |
| `0011`      | `INTEST`       | BSR len   | Drive core from BSR — used for IP-level interconnect verify |
| `0100`      | `CLAMP`        | 1 (BYPASS) | Drive pads from BSR + bypass DR, used during board-level cascades |
| `0101`      | `HIGHZ`        | 1 (BYPASS) | Float all outputs — board safety |
| `1110`      | `IDCODE`       | 32        | 32-bit IDCODE register (see §2.4) |
| `1111`      | `BYPASS`       | 1         | 1-bit bypass — mandatory reset state |

### 2.2 User (custom) instructions

| Opcode (TBD) | Mnemonic       | DR length | Function |
|-------------|----------------|-----------|----------|
| `1000`      | `SCAN_EN`      | 1         | Assert internal `scan_mode = 1` (and scan_asyncrst_ctrl, scan_clk gating). Latches in Update-IR. |
| `1001`      | `SCAN_LOAD`    | N (chain) | Selects one scan chain at a time (chain index in DR header) — TDI shifts into chain head, TDO from chain tail |
| `1010`      | `MBIST_START` | 8         | Algorithm select (8b): bit 0 = enable, 1 = March-C+, 2 = March-LR, [4:3] = SRAM target, [7:5] = reserved |
| `1011`      | `MBIST_STATUS` | 64        | 64-bit result register: fail-flag, last-failing-address, last-failing-data, retry counter |
| `1100`      | `FUSE_RD`      | 64        | Read trim/redundancy fuse latch (chip-ID / process-corner monitor) — **TBD** if fuses are present |
| `1101`      | `DEBUG_REG`   | 32        | Direct read of a small set of debug registers (link state, PHC counter LSBs) for silicon bring-up — **TBD** if we want this |

### 2.3 TAP state machine (IEEE 1149.1)

```
                                  ┌─── 1 ───────────────────────────┐
                                  │                                 │
                ┌─── 1 ──► [Test-Logic-Reset] ◄─── 1 ─── any state   │
                │            │                                       │
                │            0                                       │
                │            ▼                                       │
                │       [Run-Test/Idle] ─── 0 ──┐                   │
                │            ▲                  │                    │
                │            0                  1                    │
                │            │                  ▼                    │
                │       ┌────┴────┐       ┌─── Select-DR-Scan ──1──► Select-IR-Scan ──┐
                │       │         │       │                                            │
                │       0         0       0                                            0
                │       │         │       ▼                                            ▼
                │       │         │   [Capture-DR]                                [Capture-IR]
                │       │         │       │                                            │
                │       │         │       0  ◄── 1 ── [Exit1-DR]                       0
                │       │         │       ▼          ▲                                 ▼
                │       │         │   [Shift-DR] ────┘                            [Shift-IR]
                │       │         │       │                                            │
                │       │         │       1                                            1
                │       │         │       ▼                                            ▼
                │       │         │   [Exit1-DR] ── 0 ──► [Pause-DR] ◄── 0 ── [Exit2-DR]
                │       │         │       │                  │                  ▲     │
                │       │         │       1                  1                  │     1
                │       │         │       │                  ▼                  │     │
                │       │         │       │              [Exit2-DR] ───────────┘     │
                │       │         │       ▼                                            ▼
                │       │         │   [Update-DR]                               [Update-IR]
                │       │         │       │                                            │
                │       │         │       │                                            │
                │       └─────────┴───────┴────────────────────────────────────────────┘
                │                          (back to Run-Test/Idle or Select-DR-Scan)
                │
                └────── 5× TMS=1 from any state ► Test-Logic-Reset (asynchronous-style sync reset)
```

Implementation: synthesisable Verilog FSM (Mealy or Moore — **TBD**, but
Moore preferred for cleaner timing). The 16-state TAP is small enough
that it should not be a critical path even on a slow TCK (10 MHz target).

### 2.4 IR / DR lengths

* **IR length: 4 bits** — enough for 16 instructions; we use 13 above so
  there are 3 unused encodings reserved.
* **IR reset value: `1110` (IDCODE)** as required by 1149.1.
* **Bypass register: 1 bit.**
* **IDCODE register: 32 bits.**
* **Boundary-scan register length:** sum of BSCs across all pads — see
  §5.2 for the count. Expected ≈ 200–280 bits (TBD on final pad list).
* **Scan-chain DR length: variable, max chain length.** Selected via the
  `SCAN_LOAD` opcode's DR header — see §3.

### 2.5 IDCODE register (32 bits, IEEE 1149.1-2013 §8.13)

```
 bit  31 ──── 28 27 ──────────── 12 11 ───── 1  0
     ┌───────┐ ┌────────────────────┐ ┌──────────┐ ┌─┐
     │ VER 4 │ │     PART  16       │ │  MFG 11  │ │1│
     └───────┘ └────────────────────┘ └──────────┘ └─┘
```

| Field        | Width | Value (TBD)            | Notes |
|--------------|-------|------------------------|-------|
| Version      | 4     | `0000` (rev A0)        | Increment per metal-spin |
| Part number  | 16    | `0xTD01` (TideLink v1) | **TBD** — coordinate with SoC Labs tapeout registry |
| Manufacturer | 11    | `0x069` (Univ. of S'oton via TSMC academic — placeholder) | **TBD** — get from JEDEC if Soton has an assigned code, otherwise use an academic placeholder. Real silicon would need a real JEDEC code. |

### 2.6 Pin assignments

| Pin    | Direction | Drive            | Notes |
|--------|-----------|------------------|-------|
| TCK    | input     | 1.8 V LVCMOS     | Optional 10 MHz default; sized for 25 MHz |
| TMS    | input     | 1.8 V LVCMOS     | Pulled up internally (per spec) |
| TDI    | input     | 1.8 V LVCMOS     | Pulled up internally |
| TDO    | output    | 1.8 V LVCMOS, tri-state | Tri-stated except in Shift-IR/Shift-DR |
| nTRST  | input     | 1.8 V LVCMOS     | Active-low async reset to TAP only — **OPTIONAL per spec, but include** for clean power-up. Pulled up. |

All 5 JTAG pins are **dedicated** (not multiplexed with functional
pins). This avoids the "JTAG works only in test mode" failure mode
which has bitten silicon bring-up on previous SoC Labs vehicles.

### 2.7 TAP location — AON island

The TAP must remain operable when the main core is power-gated (during
silicon bring-up, "did my power switch turn on?" is the first JTAG
question). The TAP controller, its IR/DR, the BSR, and the IDCODE shift
register sit in the **AON (always-on) power domain**.

Cross-domain handshakes:
* TAP → core (MBIST start, scan-enable assert) — async pulse synced
  by a dual-flop synchroniser in the core's clock domain. Standard
  CDC; uses the same `WavResetSync`-style synchroniser cell that
  appears in the existing RTL (`WavResetSync.v:27`, `reset_sync_demet`).
* Core → TAP (MBIST done, scan-out) — symmetric two-flop sync, but
  also clocked by TCK on the AON side. The MBIST result register
  itself is in AON; the core's MBIST done bit gets sampled on TCK and
  shifted out via the `MBIST_STATUS` DR.

## 3. Scan stitching

### 3.1 Existing RTL hooks (already in place — wire-only work to do)

The Wlink-generated RTL already threads `scan_mode`, `scan_clk`,
`scan_asyncrst_ctrl` (and where present, `io_scan_in` / `io_scan_out`)
through the full hierarchy:

| Module                        | File:line                                                      | Hooks |
|-------------------------------|----------------------------------------------------------------|-------|
| `WavD2DGpioRx`                | `deps/.../wlink/WavD2DGpioRx.v:55-58`                          | `io_scan_mode`, `io_scan_asyncrst_ctrl`, `io_scan_clk`, `io_scan_out` |
| `WavD2DGpioTx`                | `deps/.../wlink/WavD2DGpioTx.v:2-5`                            | identical 4-port set |
| `WavD2DGpio` (8×TX + 8×RX wrapper) | `deps/.../wlink/WavD2DGpio.v:24` + 8× rep per lane         | per-lane hookup |
| `WlinkGPIOPHY`                | `deps/.../wlink/WlinkGPIOPHY.v:17, :112, :175`                 | `scan_mode`, `scan_asyncrst_ctrl`, `scan_clk` propagated to inner WavD2DGpio |
| `Wlink`                       | `deps/.../wlink/Wlink.v:100-102, :1064-1066, :1670-1672`       | `scan_mode`, `scan_asyncrst_ctrl`, `scan_clk` to PHY + reset synchronisers |
| `axi_chiplet_controller`      | `deps/.../top/axi_chiplet_controller.sv:262, :1564`            | top-of-Wlink-stack `scan_mode` |
| `tidelink_top`                | `src/rtl/tidelink_top.sv:169, :1062, :1592`                    | tidelink-top `scan_mode` — currently has **no driver**, tied at chip-top in FPGA flow |

### 3.2 Scan-mode integration plan

**Step 1.** Replace the tidelink-top `scan_mode` tieoff with a wire from
the TAP controller's `SCAN_EN` instruction output. Wires extend to
`scan_clk` (the gated TCK or a separate scan clock — see §3.6) and
`scan_asyncrst_ctrl` (gates async resets — see §7).

**Step 2.** Insert the **scan-stitching netlist** *after* synthesis. We do
**not** stitch in RTL — stitching is done by the DFT tool
(Tessent ScanShift / TetraMAX DFT-MAX / Encounter Test) which reads
the post-synthesis netlist, identifies all flops, classifies them by
clock domain (and edge), and chains them into scan chains driven by
`scan_clk`.

**Step 3.** ATPG runs on the post-stitched netlist. Vectors are loaded
through the TAP via the `SCAN_LOAD` instruction, which selects one
chain head/tail at a time. Multi-chain serial-via-JTAG is slow but
acceptable for a small design — at-speed ATE would use dedicated scan
pins; we don't ship those.

### 3.3 Scan chain count

| Domain           | Approx. flop count (TBD) | Chains | Comment |
|------------------|--------------------------|--------|---------|
| `hclk` (AHB / app) | ~30 k (XHB500 + FIFO ctrl + APB regs + addr-xlat + FC adapter) | 8 | Largest domain |
| `apb_clk`         | ~2 k (APB regfile, often = hclk in this design)                  | 1 | (Often merged into `hclk` if same source) |
| `phc_clk`         | ~3 k (PHC counter + sync + capture)                              | 2 | Independent, runs a different rate |
| `pad_clk_rx`      | ~5 k × NUM_LANES (RX deser + bitslip + IDELAYE2 cal)             | 4 | Per-lane fan-in collapsed to 4 chains; recovered clock |
| `pad_clk_tx`      | ~3 k (TX ser + word-clock divider)                               | 2 | Forwarded clock |
| `link_clk_rx`     | ~4 k (Wlink RX FSM, FC node RX, CRC) — derived from pad_clk_rx/16 | 2 | |
| `link_clk_tx`     | ~4 k (Wlink TX FSM, FC node TX, CRC) — derived from pad_clk_tx/16 | 2 | |
| `app_clk`         | ~10 k (FC + autoneg + bitslip ctrl in app domain — see Wlink.v:1546) | 4 | |
| AON / TCK         | ~0.5 k (TAP + IR/DR + BSR + MBIST controller)                    | 1 | Excluded from main chains; chained on TCK |
| **Total**         | **~80 k flops (TBD — flop-counter after synth)**                 | **~26 chains** | |

The 26-chain target falls within the 8–32 range from the brief; final
chain count is set by ATPG-tool balancing (Tessent will rebalance to
equalise chain lengths, typically ±5 %). After balancing we expect
chain lengths ~2.5–3 k flops — yielding ~3000 TCK cycles per ATPG
vector load, which at 25 MHz TCK = 120 µs per vector.

### 3.4 Per-clock-domain partitioning rationale

Each chain is **single-clock-domain, single-edge**. Mixing domains
inside one chain causes capture-mode CDC races that ATPG cannot model
correctly. The seven physical clock domains in TideLink are:

```
  ┌────────────────────────────────────────────────────────────────┐
  │                       AON (TCK domain)                          │
  │                                                                 │
  │     TAP + IR + BSR + MBIST ctrl — 1 chain, TCK clocked          │
  └────────────────────────────────────────────────────────────────┘
                                │ scan_en / scan_clk_select
                                ▼
  ┌────────────────────────────────────────────────────────────────┐
  │                  Functional core (scan_mode = 1)                │
  │                                                                 │
  │  ┌──────────────┐  ┌──────────────┐  ┌──────────────────────┐  │
  │  │ hclk dom     │  │ apb_clk dom  │  │ phc_clk dom          │  │
  │  │ ~30 k flops  │  │ ~2 k flops   │  │ ~3 k flops           │  │
  │  │ 8 chains     │  │ (merge to    │  │ 2 chains             │  │
  │  │              │  │  hclk if     │  │                      │  │
  │  │              │  │  same src)   │  │                      │  │
  │  └──────────────┘  └──────────────┘  └──────────────────────┘  │
  │                                                                 │
  │  ┌──────────────────────────────┐  ┌──────────────────────────┐ │
  │  │ pad_clk_rx (recovered)      │  │ pad_clk_tx (forwarded)   │ │
  │  │ + link_clk_rx (rx/16)        │  │ + link_clk_tx (tx/16)    │ │
  │  │ ~9 k flops, 6 chains         │  │ ~7 k flops, 4 chains     │ │
  │  └──────────────────────────────┘  └──────────────────────────┘ │
  │                                                                 │
  │  ┌──────────────────────────────────────────────────────────┐  │
  │  │ app_clk (autoneg + bitslip + FC RX/TX edge bridge)       │  │
  │  │ ~10 k flops, 4 chains                                    │  │
  │  └──────────────────────────────────────────────────────────┘  │
  │                                                                 │
  └────────────────────────────────────────────────────────────────┘
```

During scan mode, all clock-domain MUXes (the `WavClockMux` cells —
`deps/.../wlink/WavClockMux.v:1-8`) flip to the **scan_clk** input
(see `WavD2DGpioRx.v:188`: `pad_clk_scan_mux_io_i_sel = io_scan_mode`).
This means **every functional clock is bypassed and replaced by
`scan_clk`** for the duration of scan shift. Each chain still groups
flops that *in functional mode* share a clock, so when we exit scan
mode (e.g. for transition-fault LOC capture) only the correct flops
toggle.

### 3.5 Scan-disable for async-reset cells

Many flops in the design are reset by `WavResetSync` synchroniser
outputs (`Wlink.v:1528, :1534, :1546`). During scan shift, those
asynchronous resets must be **forced inactive** so they don't clobber
shifted state. The existing RTL uses `scan_asyncrst_ctrl` for this
purpose: when high, the reset path is masked by the `WavAnd` gate
inside `WavResetSync` (`WavResetSync.v:22-26, 39`). At ASIC integration:

* Top-level `scan_asyncrst_ctrl` is asserted by the TAP whenever
  `SCAN_EN` is active.
* It threads to every `WavResetSync` instance via the existing
  `io_scan_ctrl` port (`WavResetSync.v:3`).
* For flops *not* covered by `WavResetSync` (e.g. flops reset by
  `poresetn` directly), the DFT-aware std-cell flop variant
  (DFFRSCAN — std-cell-lib-dependent name) is used so that
  `scan_mode = 1` overrides the reset input. Tool flow:
  Synopsys DC `set_scan_replace_target` + `set_scan_path_disable
  -ports {poresetn hresetn}`.

### 3.6 Scan clock vs sample clock

Two scan-clocking options:

* **(A) Single scan_clk driven from TCK.** Simple, but TCK is slow
  (10–25 MHz) so ATPG load times grow proportionally.
* **(B) Scan_clk = dedicated input pin (or TCK-multiplexed) running
  at ~100 MHz.** Faster vector load. Requires an additional dedicated
  test pin (or TCK overclocking from ATE).

**Decision (TBD):** Plan (A) for v1 simplicity. If ATPG load time
proves prohibitive at the production-test step, upgrade to (B) in v2.

The **sample clock** for at-speed transition-fault capture is the
**functional clock** itself — `scan_mode` is dropped for the launch
and capture cycles, so the flop sees its real clock for two real
cycles. This is the standard LOS (launch-off-shift) approach; LOC
(launch-off-capture) is preferred for accuracy but needs higher-
quality clock chopping which we defer until at-speed is a sign-off
target.

### 3.7 ATPG tool target

**Primary:** Synopsys TetraMAX-II (modern Cadence/Synopsys academic
toolchains in the SoC Labs lab favour this). **Fallback:** Mentor
Tessent if TetraMAX licensing is constrained. Both consume the same
`.spf`/`.stil` vector format which the silicon test program can
replay.

Cell-aware library: TSMC65 cell-aware view from foundry (must be
requested from the PDK vendor — **TBD action item**).

### 3.8 Estimated coverage

| Fault model | Estimate | Confidence | Comment |
|-------------|----------|------------|---------|
| Stuck-at    | 96–98 %  | High       | 95 % floor easily achievable on a clean RTL |
| Transition  | 78–88 %  | Medium     | Tight loops in autoneg may resist LOS; LOC would push higher |
| Bridging    | 88–92 %  | Medium     | Cell-aware lib needed |
| Cell-internal | 75–85 % | Medium    | Depends on cell-lib coverage from TSMC |

Uncoverables expected (see §8 for analysis):
* Async-reset glitch synchronisers — `WavResetSync` capture flops
  are difficult for ATPG to model.
* Autoneg handshake-loop states with mutually-exclusive guard

  can never sensitise them. Will be annotated as
  `set_atpg_constraint -block` to remove from the denominator.
* Calibrator FSM stuck-at on unreachable timer values.

## 4. MBIST for FIFO SRAMs

### 4.1 Memory targets

| Macro            | Instance(s)                                  | Size            | Source |
|------------------|----------------------------------------------|-----------------|--------|
| `rf_16k`         | `u_rf` (in `tidelink_sram`)                  | 16 KB           | `src/rtl/asic/tidelink_sram.sv:48` — TSMC 65nm compiled RF |
| Wlink internal RFs | Multiple — see `WavFIFO_*.v` 20+ variants | 64–512 B each   | `deps/.../wlink/WavFIFO_*.v` — Chisel-generated, depths vary |

The Wlink "FIFOs" are mostly **register-file structures synthesised
from flops** in the current RTL (not SRAM macros). Per inspection of
`WavFIFO.v:1-145`, they are 8–16 entry FFs. These **do not need MBIST**
— they are covered by stuck-at ATPG. Only the `rf_16k` SRAM macro and
any other compiled-memory instances need MBIST.

**TBD:** confirm during physical-synthesis pass whether any other
SRAM macros get inferred for the FC node buffer or autoneg state
storage. If so, add to the BIST controller chain.

### 4.2 BIST controller

The TSMC 65 nm `rf_16k` macro ships with a **vendor BIST wrapper**
from the SRAM compiler (typically `rf_16k_bist` or similar — confirm
naming when the compiler is run). This wrapper provides:

* Test-mode input (`BIST_EN`, `BIST_CLK`, `BIST_RST`)
* Pattern-mode select (`ALGO[2:0]`)
* Done output (`BIST_DONE`)
* Fail flag + fail-address + fail-data outputs (`FAIL`, `FA[11:0]`,
  `FD[31:0]`)

For the single-SRAM case (one 16 KB macro), the BIST controller is
trivial — it's directly mapped to the JTAG `MBIST_START` /
`MBIST_STATUS` user instructions. If more SRAM instances are added
(post-PD review) we add a small controller that round-robins through
them.

### 4.3 Algorithms

| Algorithm    | Coverage                              | Cycles (16 KB) | Notes |
|--------------|---------------------------------------|----------------|-------|
| March-C+     | Stuck-at, transition, single-coupling | ~52 k          | Baseline — always run |
| March-LR     | Linked-coupling                       | ~80 k          | Tapeout-2 add-on, optional |
| NPSF (neighborhood-pattern-sensitive) | Pattern-sensitive | ~100 k–1 M | Optional, only if early silicon shows yield issues |

At 100 MHz BIST clock, March-C+ on 16 KB takes ~520 µs — completes
between two JTAG status polls. Acceptable for ATE-replayable
production test.

### 4.4 Diagnostic data path

The vendor BIST controller's fail outputs (FAIL, FA, FD) are captured
into a 64-bit shift register inside the AON island. The
`MBIST_STATUS` DR (§2.2) reads this register:

```
 bit  63 ─── 56 55 ── 53 52 ─ 33 32 ─── 1 0
     ┌────────┐ ┌───────┐ ┌──────────┐ ┌────┐ ┌─┐
     │ resv 8 │ │ algo3 │ │ FD 20    │ │ FA│ │F│
     │        │ │       │ │ (LSBs)   │ │ 32│ │ │
     └────────┘ └───────┘ └──────────┘ └────┘ └─┘
```

(Layout TBD — actual bit assignment depends on the vendor BIST
register width; the above is illustrative.)

### 4.5 JTAG hookup

```
   TAP   MBIST_START  →─── ALGO[2:0], START_PULSE ───►  BIST wrapper
   ▲                                                      │
   │ MBIST_STATUS  ◄─── DONE, FAIL, FA, FD ───────────────┘
   │
   └── via shift register, on TCK, in AON
```

### 4.6 Repair / redundancy

The `rf_16k` macro at this density typically does **not** include
spare rows or column redundancy (those start to appear at ≥ 64 KB
densities). v1 plan: **no repair**. If yield triage on test silicon
shows SRAM defects > 0.1 %, escalate to the foundry to enable
redundancy on the next compile (and we'd need to add an OTP fuse
bank for the repair address — out of v1 scope).

## 5. Boundary-scan cells (IEEE 1149.1)

### 5.1 Cell types used

| Cell type | Use case                                              |
|-----------|-------------------------------------------------------|
| BC_1      | Input observe — used for non-clock single-ended inputs |
| BC_2      | Output drive + observe — used for single-ended outputs |
| BC_4      | Input observe (asynchronous) — used for clock inputs (special clock-bypass mode means we don't gate them in normal operation) |
| BC_7      | Bidirectional input+output+enable — for tri-state I/O (I2C SDA/SCL, MDIO, future) |

### 5.2 Per-pad assignment (production 8-lane config)

| Pad group                                   | Count (8-lane) | BSR cells (each) | Cell type | Total BSR bits |
|---------------------------------------------|----------------|-------------------|-----------|----------------|
| pad_tx[7:0]                                 | 8              | 2 (drive + obs)   | BC_2      | 16             |
| pad_rx[7:0]                                 | 8              | 1 (obs)           | BC_1      | 8              |
| pad_clk_tx                                  | 1              | 2 (drive + obs)   | BC_2      | 2              |
| pad_clk_rx                                  | 1              | 1 (obs, async)    | BC_4      | 1              |
| TCK / TMS / TDI / TDO / nTRST              | 5              | (excluded — TAP itself) | n/a | 0       |
| por_n                                       | 1              | 1 (obs)           | BC_1      | 1              |
| APB bus (psel/penable/pwrite/paddr20/pwdata32/prdata32/pready/pslverr) | ~98 | 1 each | BC_1/2 | ~98 |
| AHB-sub bus (hsel/haddr32/htrans/hsize/hburst/hwrite/hwdata32/hrdata32/...) | ~120 | 1 each | BC_1/2 | ~120 |
| AHB-tx / AHB-fifo (smaller windows, ~RAM_ADDR_W=14) | ~80 | 1 each | BC_1/2 | ~80 |
| AHB-mng (manager out) | ~100 | 1 each | BC_2 | ~100 |
| PHC sideband (clk + reset + lock) | 3 | 1 each | BC_1/4 | 3 |
| Misc PMU / interrupts | ~10 | 1 each | BC_1/2 | ~10 |
| **Total BSR length (estimate)** | **~340 cells, ~440 bits (TBD)** | | | **~440** |

The exact final count depends on the final pad ring chosen by the
PD team — many of the AHB/APB buses may not actually pinout (most
SoC Labs chiplets keep them as die-only logical interfaces and only
the PHY and JTAG pads escape to the package). **TBD action: PD lead
to confirm the actual pad list.**

If only the PHY + JTAG + POR + APB-debug pads escape to the package
(plausible — the chiplet talks to its partner via D2D pads only) the
BSR drops to ~50–80 bits.

### 5.3 Special-case pads

#### 5.3.1 Clock pads
`pad_clk_rx` and `pad_clk_tx` are clock-capable inputs/outputs. The
BSR cell is **BC_4** (asynchronous input observe) which samples on
TCK without disrupting the clock — i.e. the clock pin is **not gated**
in normal operation. In **EXTEST mode** the clock pad is **driven
from the BSR** as a static value, which is required for interconnect
test on a board.

#### 5.3.2 Open-drain I2C pads (if present in v1)
v1 has no I2C autonomy at this layer (I2C autonomy is on a separate
parent fabric, per the user's "TideLink I2C autonomy" branch). If the
final pad list adds I2C SDA/SCL, those use **BC_7** with the tri-state
observe handled correctly — output-enable separate from data so the
BSR can park the open-drain in Hi-Z safely.

#### 5.3.3 Tri-state TDO
TDO is tri-stated outside of Shift-IR and Shift-DR (mandated by the
spec). The TDO pad has no BSR cell — it's *part of* the TAP, not the
core, and is permanently in the AON island.

### 5.4 BSR insertion flow

Inserted by the DFT tool (Tessent / Synopsys DFT-MAX) *after*
synthesis, *before* place-and-route. The BSDL output is generated at
the same time and is the deliverable to the board-design team for
their boundary-scan tester.

## 6. Behavioural cell replacement

The Wlink-emitted RTL uses behavioural stand-ins for std-cell-level
DFT-aware primitives. These must be replaced with the foundry's
DFT-aware std cells before tapeout:

### 6.1 `WavResetSync` (`deps/.../wlink/WavResetSync.v`)

**Behavioural:** Two flops in series (`reset_sync_demet`), with an
`WavAnd` masking the input by `~scan_low_winv_io_z` (i.e. by
`~io_scan_ctrl`, see lines 39–43). This *describes* a scan-aware
synchroniser correctly but the actual gate-level implementation
should use the foundry's **dual-synchroniser cell with built-in
DFT bypass** (e.g. `SYNCDFFRQX*` in TSMC65 std-cell lib).

**ASIC replacement:** Map `WavResetSync` to `tlk_reset_sync_stdcell`
which is a wrapper around the TSMC65 dual-sync DFT flop. Preserves
the same port interface so no upstream RTL changes.

### 6.2 `WavClockGate` (`deps/.../wlink/WavClockGate.v`)

**Behavioural:** A behavioural latch-AND structure with `io_test_en`
ORed into the enable. Has a `io_test_en` input port already
(`WavClockGate.v:4`) which is correctly tied to `scan_mode`
(`WavD2DGpioTx.v:103`: `hs_clk_gated_wcg_io_test_en = io_scan_mode`).

**ASIC replacement:** Map directly to TSMC65 ICG cell (e.g. `CKLNQX*`)
which has a native `TE` (test-enable) pin. The `io_test_en` → `TE`
mapping is direct.

### 6.3 `WavClockInv` (`deps/.../wlink/WavClockInv.v`)

**Behavioural:** Plain inverter. ASIC: replaced by a clock-tree-aware
inverter (`CKINVX*`) — handled automatically by clock-tree synthesis,
no special DFT consideration.

### 6.4 `WavClockMux` (`deps/.../wlink/WavClockMux.v`)

**Behavioural:** A 2:1 mux on clocks (`io_i_sel, io_i_a, io_i_b, io_o_z`).
This is the cell that picks **functional clock vs scan_clk** during
scan shift (sel = `scan_mode`, b = `scan_clk` — `WavD2DGpioRx.v:188,
:190`).

**Risk:** A naive logical mux causes a clock glitch when `sel`
switches. ASIC needs a **glitch-free clock mux** (e.g. `CKMUX2X*`
from TSMC65) which is a two-flop sync structure that handshakes the
transition between clocks. The DFT lead must verify that *every*
`WavClockMux` instance is mapped to the glitch-free variant — a stuck
default mux would corrupt scan vectors **and** the recovered clock
in normal operation.

### 6.5 Demet / DFF cells

Random `WavDemetSet`, `WavDff`, etc. behaviourals also appear inside
the Wlink RTL (e.g. `WavResetSync.v:27`). These map to standard
DFT-aware DFFs (`SDFFR*Q*` family in TSMC65) — the scan replacement
is performed by Synopsys DC's `compile_ultra -scan` automatically.

### 6.6 Summary table

| Behavioural cell | Std-cell target (TSMC65, TBD) | DFT property |
|------------------|-------------------------------|--------------|
| `WavResetSync`   | `tlk_reset_sync_stdcell` (wrapper around `SYNCDFFRQX*`) | scan-bypass on `io_scan_ctrl` |
| `WavClockGate`   | `CKLNQX*` ICG | `TE` pin overrides enable in scan |
| `WavClockInv`    | `CKINVX*` | no DFT change |
| `WavClockMux`    | `CKMUX2X*` (glitch-free) | `sel` from `scan_mode` |
| `WavDff*`        | `SDFFR*Q*` (scan flop) | auto-replace by DC |
| `WavDemetSet`    | `SYNCDFFRQX*` x2 | dual-flop sync, DFT-bypass |

## 7. Scan-disable signals

### 7.1 `scan_asyncrst_ctrl` — the under-wired signal

`io_scan_asyncrst_ctrl` is propagated through the entire hierarchy
(see §3.1) but in the FPGA flow it's tied to `1'b0` at the top —
meaning async resets are **not** gated during nominal operation. In
the ASIC flow:

* TAP asserts `scan_asyncrst_ctrl = 1` whenever `SCAN_EN` is active.
* When asserted, `WavResetSync.v:39` (`scan_low_winv_io_z =
  ~io_scan_ctrl`) drives the `WavAnd` mask to 0, holding the
  synchroniser's reset input deasserted regardless of the functional
  `io_reset_in`.
* This prevents reset glitches from clobbering scan-shifted state.

### 7.2 Other test-control signals needed

Beyond the existing hooks, the ASIC needs:

* **`scan_pll_bypass`** — bypass any PLLs / clock dividers during
  scan. v1 has no PLL on the chiplet itself (clocks are forwarded
  from outside), so this is a no-op. **Mark as N/A for v1.**
* **`scan_idelay_bypass`** — disable the IDELAYE2 calibrator in
  scan mode. The IDELAYE2 is FPGA-only (`USE_IDELAY=1` only in the
  FPGA wrapper — `tidelink_top.sv:65`); for the ASIC, the cal block
  is replaced by a static delay (TBD: confirm with PD team) or by
  an unrelated all-digital DLL. If the latter, the DLL needs its own
  scan-bypass.
* **`scan_obs_en`** — observe-point enable. Standard tool-inserted
  test point; managed by the DFT tool, no RTL change.
* **`scan_test_clk_en`** — top-level enable that gates the scan clock
  in functional mode (saves power; mandatory for sign-off LEC).

### 7.3 Tie-off audit

A pre-tapeout LEC (Logical Equivalence Check) gate must confirm:

* `scan_mode == 0` in functional mode at the chip top.
* All scan-mux selectors collapse to functional clocks.
* `scan_asyncrst_ctrl == 0` in functional mode (resets enabled).

These three checks gate the tapeout sign-off.

## 8. Coverage strategy + sign-off targets

### 8.1 Targets (recap, see §1.3)

* Stuck-at: 95 % hard, 97 % stretch.
* Transition: 80 % report-only.
* Bridging: 90 % report-only.
* MBIST: 100 % mandatory.

### 8.2 Coverage drop-from-100% accounting

We work bottoms-up — for each design block, list the known
ATPG-resistant constructs and confirm we have a coverage exclusion
or alternative plan:

| Block | Construct | Issue | Mitigation |
|-------|-----------|-------|------------|
| `WavResetSync` | dual-flop async sync | ATPG cannot launch deterministic transitions on reset path | Tool-aware exclusion via `set_atpg_constraint -block` on the async-reset graph |
| autoneg FSM (`Wlink.v` autoneg block) | Mutually-exclusive guard states | Some states never reached in valid sequences | RTL annotation `// pragma atpg unreachable` + tool exclusion |
| Calibrator timer / `count` registers | Saturating counters — many never reach max in any vector | Replace with bounded counter or accept ATPG loss | Accept loss; <0.5 % impact |
| Wlink credit RX/TX | Initial-state-dependent counters | Need to specify init state for ATPG | `set_atpg_init_state` directive |
| CRC LFSR | XOR feedback shift register — high fan-in | Cell-aware test may flag many "uncoverable" bridges inside the XOR tree | Cell-aware lib needed |
| FIFO pointer comparators | One-hot pointer compare cascades — high re-convergence | Add observe points if coverage gap > 1 % | Tool-inserted observe pts |
| `WavClockMux` outputs | Glitch-free mux state — sync flops with constraints | Treated as primary clock by ATPG | Black-box during scan; modelled separately |

### 8.3 Coverage sign-off flow

1. ATPG run with default settings — record initial coverage.
2. Add per-block exclusions / init states — record net coverage.
3. Add tool-inserted observe points until target hit — record final.
4. **Sign-off requirement: stuck-at ≥ 95 %, MBIST = 100 %.** If a
   block does not hit 95 % after exclusions and observe points, the
   block is flagged for RTL re-spin (escalation to architecture).

### 8.4 ATE pattern budget

* Scan vectors: ~3 000 patterns × ~3 k chain depth × ~26 chains
  / 1 (serialised via TCK) ≈ ~6 s of TCK time at 25 MHz. Acceptable
  for engineering ATE — production-test would require parallel scan
  pins (deferred).
* MBIST: ~520 µs per algorithm per macro × 1 macro × 1 algo (March-C+)
  = ~0.5 ms. Negligible.

## 9. Test sequence (silicon bring-up)

The first power-on of TideLink-A0 silicon. Each step has a pass/fail
gate; failure at any step halts before functional verification.

```
   ┌──────────────────────────────────────────────────────────────┐
   │ STEP 1: Power on                                             │
   │   VDD_AON → VDD_CORE → POR pulse → wait ≥ 1 ms              │
   │   (POR triggers the WavResetSync chain — Wlink.v:1528 etc)  │
   │   GATE: VDD currents in expected range; POR observed clean. │
   └──────────────────────────────────────────────────────────────┘
                                  │
                                  ▼
   ┌──────────────────────────────────────────────────────────────┐
   │ STEP 2: JTAG hello                                           │
   │   TMS = 11111 (5 cycles, force Test-Logic-Reset)             │
   │   Issue IDCODE: 32 shifted bits should match expected        │
   │   (e.g. 0xTD010069_1 or whatever §2.4 settles on)            │
   │   GATE: IDCODE returns valid pattern → TAP alive.            │
   └──────────────────────────────────────────────────────────────┘
                                  │
                                  ▼
   ┌──────────────────────────────────────────────────────────────┐
   │ STEP 3: Boundary-scan SAMPLE (read pad state)                │
   │   Issue SAMPLE, shift out the BSR.                          │
   │   GATE: All BSR cells return valid (0 or 1, no float).      │
   │   Diagnostic only — no fail action.                          │
   └──────────────────────────────────────────────────────────────┘
                                  │
                                  ▼
   ┌──────────────────────────────────────────────────────────────┐
   │ STEP 4: Boundary-scan EXTEST                                 │
   │   Drive pads from BSR. Walk-one and walk-zero patterns on    │
   │   pad_tx / pad_clk_tx outputs.                              │
   │   GATE: External monitor (oscilloscope or board partner)    │
   │   confirms each output toggles. Confirms pad ring integrity. │
   └──────────────────────────────────────────────────────────────┘
                                  │
                                  ▼
   ┌──────────────────────────────────────────────────────────────┐
   │ STEP 5: MBIST                                                │
   │   Issue MBIST_START with March-C+ select.                    │
   │   Poll MBIST_STATUS until DONE bit set (~500 µs).            │
   │   GATE: FAIL bit = 0. If FAIL = 1, capture FA, FD for       │
   │   silicon-failure log.                                       │
   └──────────────────────────────────────────────────────────────┘
                                  │
                                  ▼
   ┌──────────────────────────────────────────────────────────────┐
   │ STEP 6: Stuck-at scan ATPG                                  │
   │   Issue SCAN_EN; for each scan chain (1..26):               │
   │     Issue SCAN_LOAD(chain_idx); shift in vector;             │
   │     Drop scan_mode for one functional cycle (capture);       │
   │     Re-assert scan_mode; shift out chain state.              │
   │   Compare against expected from STIL.                       │
   │   GATE: ≤ 1 mismatch per 100 patterns acceptable for         │
   │   engineering bring-up (production gates much tighter).      │
   └──────────────────────────────────────────────────────────────┘
                                  │
                                  ▼
   ┌──────────────────────────────────────────────────────────────┐
   │ STEP 7: Drop scan_mode → functional bring-up                 │
   │   - APB read of REGISTER_MAP IDs                            │
   │   - Calibrator enable on a paired chip                       │
   │   - Autoneg observe                                          │
   │   - Cross-link loopback check                                │
   │   GATE: link comes up and data flows (handover to            │
   │   functional bring-up plan, separate doc).                   │
   └──────────────────────────────────────────────────────────────┘
```

## Appendix C — Glossary

| Acronym | Meaning |
|---------|---------|
| ATPG    | Automatic Test Pattern Generation — software that generates scan vectors |
| BSR     | Boundary Scan Register — the chain of cells surrounding the I/O ring |
| BSDL    | Boundary Scan Description Language — text file describing the BSR for board-level testers |
| BIST    | Built-In Self Test (often M-BIST for memory) |
| BSC     | Boundary Scan Cell (one bit of the BSR) |
| DFT     | Design For Test |
| ICG     | Integrated Clock Gate — clock-gating std cell with built-in latch and TE input |
| IDCODE  | 32-bit JTAG identifier register (vendor/part/version) |
| IR / DR | Instruction Register / Data Register (JTAG) |
| LBIST   | Logic BIST (in-chip pseudo-random pattern generation; not used here) |
| LOC     | Launch-Off-Capture — at-speed transition-fault test launch method |
| LOS     | Launch-Off-Shift — alternative at-speed launch method |
| MBIST   | Memory BIST |
| NPSF    | Neighborhood Pattern Sensitive Faults |
| SPF     | Synopsys Pattern Format |
| STIL    | Standard Test Interface Language (IEEE 1450) |
| TAP     | Test Access Port — the JTAG FSM controller |
| TCK     | Test Clock — JTAG bit-shift clock |
| TDI/TDO | Test Data In/Out |
| TMS     | Test Mode Select |
| nTRST   | Test Reset (active-low, optional in 1149.1) |
