### 2.1 Stuck-at (combinational)

| Domain | Target | Notes |
|---|---|---|
| `tidelink_top` excluding Wlink Chisel | ≥ 99.0 % | Standard TSMC65 sign-off bar; the design is small (≈25-35k flops post-synth estimate). |
| Wlink Chisel-generated cells | ≥ 97.0 % | Chisel auto-gen residuals (latched flops, redundant decode) typically drag overall by 1-2 %. Document waivers per `run_lec.tcl` 2-pass strategy precedent. |

| rf_16k SRAM | tested via MBIST, not ATPG | Memory faults addressed in §4; CTL model wraps the macro as a black-box during ATPG. |

### 2.2 Transition (at-speed)

| Domain | Target |
|---|---|
| `tidelink_top` non-Wlink | ≥ 95.0 % |
| Wlink | ≥ 90.0 % |
| Launch-on-capture (LoC) preferred over launch-on-shift; LoS as fallback for hard-to-detect paths. |
| At-speed clock: `scan_clk` runs at functional `hclk` rate during capture; shift runs at 50 MHz (margin from `scan_asyncrst_ctrl` toggle). |

### 2.3 MBIST coverage (rf_16k)

| Test | March pattern | Faults covered |
|---|---|---|
| MATS+ | r0w1r1, r1w0r0 | stuck-at, transition (basic) |
| March-C- | full March-C variant | stuck-at + transition + coupling (CF) + address decoder (AF) |
| Retention | write checkerboard, hold ≥ 1 ms, read | data-retention faults (DRF) |
| EMA/EMAW sweep | run March-C- at EMA=000, 011, 111 | weak-cell margin |

Target: 100 % cell coverage on the single rf_16k instance. The macro is
small (4096 × 32 = 131 072 bits) so a single March-C- pass at functional
clock takes ≈ 16 ms; full retention pass adds 1 ms hold per pattern.
Tape-out gate: BIST-status APB read returns `PASS=1`, `DONE=1` within a
documented bound after `mbist_en` deassert.

### 2.4 JTAG / boundary scan

V1 single-die decision: **defer**. The chiplet's only top-level pads are
the GPIO PHY (data + clock, 8 + 1 each direction), APB, AHB, I2C, and a
handful of strap/IRQ signals. With pad-count < 80 the loss of BSDL
testability is acceptable; SoC integrators can use the chiplet's own APB
to exercise the periphery.

If the integrator insists on a TAP: §5 below scaffolds a minimal
1149.1-2013 TAP wrapper that gets instantiated by `tidelink_dft_wrapper`
when parameter `INCLUDE_TAP=1`. Closure (writing the BSDL, instantiating
the boundary cells on every IO) is a 2-week task and is **not** done in
this scaffold.

## 3. Scan architecture

### 3.1 Style

**Mux-scan (mux-D)**, not LSSD. Rationale:
- TSMC65 standard-cell library uses mux-D scan flops (`*SDFF*` family in
  `tcbn65gplus*.db`).
- Mux-D minimises area overhead vs LSSD (one extra mux per flop vs two
  latches) and matches the synthesis library defaults Fusion Compiler is
  already configured for.
- ATPG with TestMAX/Tessent on mux-D is the most-supported path and
  needs no special clock-tree handling.

### 3.2 Chain count and length (proposal — to be refined post-synth)

Estimated post-synth flop count: **25 000-35 000** (Wlink ≈ 18-22 k,
TideLink ≈ 6-10 k, GPIO-PHY ≈ 1-3 k). Proposal:

| Chain | Domain | Estimated flops | Anchor pins |
|---|---|---|---|
| `chain[0]` | `hclk` (AHB / app domain) | 8 k | `scan_in[0]` → `scan_out[0]` |
| `chain[1]` | `hclk` cont'd (Wlink hclk side) | 8 k | `scan_in[1]` → `scan_out[1]` |
| `chain[2]` | `hclk` cont'd (XHB500 + addr translator) | 6 k | `scan_in[2]` → `scan_out[2]` |
| `chain[3]` | `link_clk` (Wlink tx/rx link domains) | 4 k | `scan_in[3]` → `scan_out[3]` |
| `chain[4]` | `pad_clk_rx` (RX capture / IDELAY tap chain) | 2 k | `scan_in[4]` → `scan_out[4]` |
| `chain[5]` | `phc_clk` (PTP capture flops) | 1.5 k | `scan_in[5]` → `scan_out[5]` |
| `chain[6]` | `apb_clk` (APB regs, gpio_phy regs) | 0.5 k | `scan_in[6]` → `scan_out[6]` |
| `chain[7]` | wildcard / spare for routing balance | balance | `scan_in[7]` → `scan_out[7]` |

8 chains × ~4 k flops max → shift length ≈ 4 k cycles per pattern (vs
~30 k for a single chain). At 50 MHz shift this is 80 µs per pattern
vs 600 µs — material to ATPG runtime and tester time.

> **Hook implication:** the existing 1-bit `scan_in` / `scan_out` ports
> on `tidelink_top` must be widened to 8-bit, or the DFT wrapper must
> introduce a separate 8-bit chain bus that bypasses the top-level
> stub. The wrapper scaffold (§6 + `src/rtl/asic/tidelink_dft_wrapper.sv`)
> takes the second path and leaves `tidelink_top`'s 1-bit stub alone.

### 3.3 Scan-enable polarity

`scan_en` (== `scan_shift`) is **active-high**. Tied to 0 in functional
mode (the existing `run_lec.tcl` pin-down already does this). The DFT
tool will replace every functional flop with a mux-D scan flop where the
mux is selected by `scan_en`.

### 3.4 Clock during scan

| Phase | Clock source | Rate |
|---|---|---|
| Scan-shift | `scan_clk` (test-mode-gated) | 50 MHz |
| Scan-capture (stuck-at) | `scan_clk` | 50 MHz (slow capture acceptable) |
| Scan-capture (transition LoC) | `hclk` (functional), `phc_clk`, `link_clk`, `pad_clk_rx` | nominal corner — `hclk` = 100 MHz, others per their functional rate |

All functional clock-gating cells (`WavClockGate`, FC-inserted ICG) must
have a TE/TEST_EN input that is OR-ed with `scan_en`. The existing
Wlink-generated `WavClockGate.v` already exposes a TE-equivalent
pattern; the FC ICG library cell has `TE`. The DFT script must verify
both ahead of insertion.

### 3.5 Async resets during scan

`hresetn`, `poresetn`, `apb_rst_n`, `phc_resetn`, `link_rx_rst_n` are all
async. During scan-shift they must be held high (de-asserted) so flops
don't reset mid-shift. The existing `scan_asyncrst_ctrl` port is the
mux-select that gates the reset tree to a constant 1 in test mode. It is
already pinned to 0 in functional LEC (`run_lec.tcl:269`) — DFT
insertion must wire it through every reset-gating cell inserted on the
reset tree.

## 4. MBIST strategy

### 4.1 Choice of controller

Two options surveyed:

| Option | Pros | Cons | Decision |
|---|---|---|---|
| **Tessent MemoryBIST** | Vendor-recommended; CTL model directly consumable; supports redundancy (we don't need this — rf_16k has 0 redundant columns); generates RTL + patterns | License required; learning curve | **PREFERRED** if licence is available |
| **Custom March-C- controller** | No licence; small (~200 flop FSM + counter); fully understood | No diagnosis support; no automatic BIRA; engineer-written = engineer-tested risk | **FALLBACK** — scaffold this if Tessent licence is not granted |

The scaffold in `syn/asic/dft/insert_mbist.tcl` supports both. Default
is Tessent; setting `MBIST_FLOW=custom` falls back to the
hand-written controller skeleton (which still needs writing — `insert_mbist.tcl`
emits a TODO note for the custom path).

### 4.2 Interface to the SRAM

The existing wrapper `tidelink_sram` instantiates rf_16k with EMA/EMAW
tied to default and RET1N tied to 1 (normal operation). To support
MBIST we expose these:

| rf_16k pin | New tidelink_sram port | Default (functional) | MBIST drive |
|---|---|---|---|
| EMA[2:0] | `mbist_ema_i[2:0]` | 3'b000 | swept 000/011/111 |
| EMAW[1:0] | `mbist_emaw_i[1:0]` | 2'b00 | swept |
| RET1N | `mbist_ret1n_i` | 1'b1 | toggled to 0 during retention test, then back to 1 with hold |
| CLK | `clk_i` (was CLK) | functional | switched to BIST clock by MBIST controller |
| CEN, WEN, GWEN, A, D | functional | functional | driven by MBIST controller pattern generator |
| Q | `rdata` | functional | observed by signature compactor in MBIST controller |

This change is **not** made in this scaffold (it would invalidate every
existing unit test that drives `tidelink_sram`). It is documented here
and in `src/rtl/asic/tidelink_dft_wrapper.sv` so the closure engineer
can apply it as a single coordinated change.

### 4.3 BIST control / status (APB-visible)

A new APB register block `tidelink_mbist_regs` (NOT created in this
scaffold) sits in TideLink's APB region at offset `0x4000` (currently
addr-translator territory — TBD final offset). Register fields:

| Offset | R/W | Bits | Field | Notes |
|---|---|---|---|---|
| 0x00 | R/W | 0 | `mbist_en` | Start BIST run |
| 0x00 | R/W | 1 | `mbist_retention_en` | Include retention test |
| 0x00 | R/W | 7:4 | `mbist_algo_sel` | 0=MATS+, 1=March-C-, 2=March-LR |
| 0x04 | R | 0 | `mbist_done` | High when run complete |
| 0x04 | R | 1 | `mbist_pass` | High when all patterns passed |
| 0x04 | R | 23:8 | `mbist_fail_addr` | First failing word address (if !pass) |
| 0x08 | R | 31:0 | `mbist_signature` | Compacted signature for diagnosis |

### 4.4 Run-time

| Algorithm | Cycles per word | Total cycles (4096 words) | Wall-time @ 100 MHz |
|---|---|---|---|
| MATS+ | 5 | 20 k | 200 µs |
| March-C- | 11 | 45 k | 450 µs |
| Retention (write + 1 ms hold + read) | 6 + 100 k + 4 | 100 k | 1 ms |
| March-C- × 3 (EMA sweep) | 11 × 3 | 135 k | 1.35 ms |
| **Full BIST run** | | | **≈ 3.0 ms** |

This is comfortably within an ATE test budget.

## 5. JTAG / boundary scan plan

**V1 decision: defer.** Single-die chiplet, internal SoC integrator owns
the pad ring after integration. Document the decision in the
integration guide.

If a TAP is later required:
- Use a vanilla 1149.1-2013 TAP controller (Synopsys DesignWare or
  open-source equivalent).
- Instructions to support: `BYPASS`, `IDCODE`, `SAMPLE`, `PRELOAD`,
  `EXTEST`, `INTEST` (optional), `SCAN_N` (optional), `MBIST_RUN` (user
  instruction to launch BIST without APB access).
- One boundary cell per IO pad. Pad count ≈ 60-80 → BSDL file ~1500
  lines. Effort: 2 weeks including BSDL validation.

The wrapper file `src/rtl/asic/tidelink_dft_wrapper.sv` includes an
`INCLUDE_TAP` parameter that gates a TAP placeholder. Setting it to 1
without writing the boundary cells will cause a clean elaboration but
the TAP will not actually drive any IO — this is a TODO for the closure
phase.

## 6. RTL hooks needed

### 6.1 Top-level test-mode signals

A new `tidelink_dft_wrapper` (this scaffold creates the skeleton)
exposes:

```
input  wire        test_mode        // global test-mode qualifier
input  wire        scan_en          // == scan_shift; active-high
input  wire        scan_clk         // test-mode clock; SDC `create_clock`
input  wire [7:0]  scan_in          // 8 mux-scan chain heads
output wire [7:0]  scan_out         // 8 mux-scan chain tails
input  wire        scan_asyncrst_ctrl  // hold async resets de-asserted in test
input  wire        mbist_en         // start MBIST
output wire        mbist_done
output wire        mbist_pass
input  wire        tap_tck          // (only if INCLUDE_TAP=1)
input  wire        tap_tms          // ditto
input  wire        tap_tdi          // ditto
output wire        tap_tdo          // ditto
input  wire        tap_trstn        // ditto, async
```

The wrapper instantiates one `tidelink_top` and one `tidelink_mbist_ctrl`
(placeholder), with multiplexing on the SRAM interface so that BIST
patterns drive the macro when `mbist_en=1` and functional traffic drives
it otherwise.

### 6.2 Async-CDC marking

The following modules contain 2-FF synchronisers that **MUST NOT** be
scan-replaced (the synchroniser is the entire safety mechanism — putting
the scan path through it breaks metastability handling):

- `tidelink_phc_cdc` — all `*_sync_pre`, `*_sync` flops
- `WavMultibitSync*`, `WavDemetReset*`, `WavDemetSet*` (Wlink-generated)
- `tidelink_gpio_phy_apb_regs` — `thresh_sync*`, `noise_mode_sync*`,
  `clear_toggle_sync*`, all `_rd_sync*` 2-FF chains
- `xhb500_sync.sv` — the XHB500 reset synchroniser

These get `set_dont_scan` in `insert_scan.tcl` (and corresponding
`dont_touch` so the tool doesn't optimise them away).

### 6.3 ICG hookup

Every clock-gating cell — both functional CG (`WavClockGate` in Wlink,
FC-inserted ICGs after synth) and the test-mode gates added by the DFT
tool — must have its TE/TEST_EN input wired to `scan_en | test_mode`.
The DFT insertion script handles this for tool-inserted ICGs; the
`WavClockGate` instances need a one-time RTL adjustment (out of scope
for this scaffold — flagged for closure).

### 6.4 Reset tree

`scan_asyncrst_ctrl` already exists at the top level. The DFT tool
inserts a mux on each async-reset input of every flop so that
`scan_asyncrst_ctrl=1` overrides the functional reset to a constant
de-asserted value. The existing top-level pin connects to this.

### 6.5 SRAM scan-protect

`tidelink_sram` must be marked `dont_scan` (the macro is not scannable).
The DFT script issues `set_dont_scan [get_cells -hier u_rf]`.

## Appendix B. Outstanding human decisions

1. **Tessent vs custom MBIST.** Decision required before the closure
   engineer can start. If Tessent: confirm licence. If custom: someone
   has to author ≈ 400-600 LOC of controller + APB-visible status regs.
2. **TAP yes/no for v1.** Default is no; if any SoC integrator's BSP
   needs boundary scan this flips.
3. **`scan_in` widening.** The current 1-bit top-level chain stub came
   from Wlink — keeping it parallel to the new 8-chain wrapper bus is
   fine for the scaffold, but the final tape-out top must rationalise to
   one scheme. Recommend: collapse the 1-bit stub into chain 0 of the
   8-chain bus.
4. **`scan_clk` source on the integrator board.** Is the integrator
   providing a dedicated test clock, or do we mux off `hclk`? If the
   latter, the SDC needs a `create_generated_clock` rather than the
   independent `create_clock` assumed in §3.4.
5. **ATPG corner.** Tape-out usually runs ATPG at slow corner (SS, low V,
   hot). Confirm with the timing engineer; this affects shift frequency
   and gating cell margins.
