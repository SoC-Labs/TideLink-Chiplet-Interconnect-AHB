## 2. ASIC CONSTRAINTS / TAPEOUT READINESS

**Verdict: NOT READY.** The rationale document (`docs/reference/ASIC_TIMING_CONSTRAINTS.md`) is normative-quality and the hand-written SDC is thoughtfully designed — but the constraint set *as executed* is far weaker than the set *as written*, and nothing in the flow catches the gap. 12 of 14 findings survived adversarial verification; the two reversals made the picture **worse**, not better.

### Blocker 1 — the functional link clock does not exist in the constraint set; `scan_clk` times 68% of the design
The Wlink link clocks are ÷16 counter outputs (`deps/axi-chiplet-controller/logical/wlink/WavD2DGpioRx.v:206` `~adj_count[3]`; `src/rtl/local_overrides/WavD2DGpioTx.v:330` `~count[3]`), each muxed against `scan_clk` under `io_scan_mode`. There is **no** `create_generated_clock` for either and **no** `set_case_analysis` on `scan_mode` anywhere under `syn/asic` (repo-wide grep: zero hits). Measured consequence, `reports/03a_cts_build.qor.rep:50-60,71-81`: CTS built `scan_clk` with **14,142 sinks** of 20,907 (67.6%) — the entire link layer and PHY — while `user_ref_clk` has **6** and `pad_clk_tx_fwd` has **0**. Three effects: the link domain is closed at 10 ns instead of 4; the `{scan_clk}` async group false-paths every Wlink↔core path; and both ends of the a2l/l2a synchronisers collapse onto one clock (`05_signoff.scen_slow.hold.rep:50-51` shows `ack_nack_fifo/write_ptr_logic/ptr_reg[0]` *and* its `sync_wptr_demet/f1_reg[0]` both "clocked by scan_clk") — strictly worse than "waived and false-pathed". The SGDC gets this right (`cdc/tidelink_top.sgdc:57,133`; `cdc/axi_chiplet_controller.sgdc:30` declares `link_rx_clk_o` at 64 ns); the STA set never received the same treatment.
**Fix:** `set_case_analysis 0` on `scan_mode`/`scan_shift`/`scan_asyncrst_ctrl` in mode `func`; declare both divided clocks `-divide_by 16` (TX off `user_ref_clk` at the `count[3]` flop, RX off `pad_clk_rx` at `adj_count[3]`); rebuild CTS and expect ~14k sinks to move; then re-derive the async groups — the link clocks are *derived* from `pad_clk_rx`/`user_ref_clk` and must not inherit `scan_clk`'s group. **Treat every link-domain timing number in this build as void.**

### Blocker 2 — the slow corner was signed off with no uncertainty, no I/O delays and no derate `[CORRECTED — this is new, and it refutes "MCMM is set up correctly"]`
`syn/asic/scripts/tidelink.FC.read_design.tcl` applies `set_clock_uncertainty` (:211-212), `set_input_delay` on `all_inputs` (:233) and `set_output_delay` on `all_outputs` (:236) **without ever calling `current_scenario`**. `scen_fast` is created last (:160) and is therefore current, so all of it landed in `scen_fast` only. Tool proof: `reports/07_pre_timing.rep` lists **607** distinct TCK-012 ports under `Corner:'slow'` and exactly **one** under `Corner:'fast'` — `hresetn`, the single port the script deliberately excludes (:220-224). Every `input external delay 1.00` / `output external delay -1.00` / `clock uncertainty -0.35` line in both signoff reports sits on a fast-corner path. `pad_rx[*]`, applied per-scenario from the SDC, is absent from TCK-012 in both corners — the control that proves the split is real. **`scen_slow` (WCCOM) — the setup-signoff corner — was placed, CTS'd, routed and signed off with zero clock uncertainty and zero boundary I/O constraints.** Its reported Setup WNS of `-0.00` (`05_signoff.qor.rep:14`) has no margin subtracted at all. Compounding: there is **no `set_timing_derate` anywhere in the repo** ("Clock derating is disabled", `07_check_clock_trees.rep:11`), no `set_max_transition`/`set_max_capacitance`, and the `pad_rx`→capture arc closes at exactly `slack (MET) 0.00` with 0.55 ns of launch-vs-capture clock-network asymmetry (`03c_cts_final.qor.rep:40-73`). The one check that would have caught it — `check_timing`, reporting 48,357 unconstrained endpoints and 608 undelayed inputs — is scored **PASS**, because `summarise_check` (`7_drc.tcl:150-181`) greps only for `Total N EMS messages : N errors` and falls through to PASS on a miss. Same vacuous-gate shape as the 2026-07-30 hwtest bug.
**Fix, in order:** wrap the `read_design` constraint block in an explicit per-scenario loop; apply uncertainty over `[all_clocks]` per scenario; add `set_timing_derate -early/-late` for both corners; add DRC limits; move `check_timing` into `5_signoff.tcl` per active scenario and gate on TCK-001/002/012 counts. Then re-close — expect real negative slack on the `pad_rx` arc.

### Blocker 3 — the SDC aborts at line 168, so the TX eye and the lane-skew bound were never applied, and the handoff collateral does not describe the block
