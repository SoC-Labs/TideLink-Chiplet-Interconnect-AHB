**Build:** v36 = `feat/phy-v2-integration` @ `2740943` (= v35 `0d55efb` + the link-rate
drop `9aee1d3` + v36 helpers `2740943`), `pynq-z2-pair-all` / `-flip-all`, staged at

(sha256 `c30079c6…` non-flip / `6aa1c1b6…` flip; sha verified both ends).
**Boards:** bridge1 = z2_02 (192.168.4.101, non-flip) ↔ z2_03 (192.168.6.101, flip).
**Goal:** lower the FPGA link rate 25 → 6.25 MHz (4×, matching the silicon-validated
PHY-BIST) to give the new PHY's WORD_PIN_AUTO aligner the eye margin v35 lacked, then
reach bilateral FCSM LINK_IDLE + M→S word crossing.

**OUTCOME: PARTIAL — improved over v35 but the same one-directional blocker remains.**
The rate drop did what it could: the A→B (z2_02 TX → z2_03 RX) direction now reaches
**full fcsm=4 (LINK_IDLE, cr=1, ck=1)** *deterministically and stably*, where v35 only
got there via the freeze trick and less reliably. But the **z2_03→z2_02 (flip-TX →
non-flip-RX) direction still never decodes the FCSM short packet (CR)** — identical
direction and signature to v35 — so bilateral LINK_IDLE is not reached and no M→S data
word crosses. The blocker is now demonstrably **structural (word/byte-phase), not eye
margin**: it is fully deterministic across redeploys and immune to every runtime knob.

## 1. The rate change (Task 1)

Ratio chosen: **4× slower** (25 → 6.25 MHz), replicating the silicon-validated
PHY-BIST config exactly (`tidelink-gpio-phy-deskew/fpga/targets/pynq-z2-phy-bist-pair`,
`clk_out1 = 6.250`, which ran autonomous bilateral `link_up` 3/3 + 30-min soak on
THESE boards).

* The PHY pad clock == `user_ref_clk` (== `io_hsclk`) **1:1** — this PHY has no
  internal pad-clock divide (`WavD2DGpio: io_pad_clk_tx = gpiotx_0_io_pad_clk`, driven
  off `io_hsclk`). So 6.25 MHz `user_hsclk` ⇒ 160 ns pad/link period (25 MHz ⇒ 40 ns).
* In the v35 BD, `clk_wiz clk_out1` feeds `tidelink_0/{hclk, user_ref_clk, scan_clk}`
  together, so dropping `CLKOUT1_REQUESTED_OUT_FREQ` 25.000 → **6.250** takes the whole
  AHB/APB/control stack to 6.25 MHz too — exactly as the BIST runs its entire stack at
  6.25 MHz (proven fine). `clk_out2` (phc_clk, 25 MHz) and `clk_out3` (200 MHz
  IDELAYCTRL ref) left unchanged — PHC is not in the link path / not exercised here.

Files changed (both `pynq-z2-pair-all` AND `pynq-z2-pair-flip-all`), commit `9aee1d3`:

| File | Change |
|------|--------|
| `tidelink_design.tcl` | `CLKOUT1_REQUESTED_OUT_FREQ` 25.000 → **6.250** |
| `*_timing.xdc` | `create_clock pad_clk_rx` 40.000 → **160.000** ns |
| `*_timing.xdc` | `set_output_delay pad_tx` ±5 → **±20** ns (period-scaled 4×, same 12.5%-of-period fraction; far die samples mid-cell so ≥60 ns margin) |
| `*_timing.xdc` | `set_input_delay pad_rx` ±4 ns, `set_max_delay` 8 ns, `set_bus_skew` 2 ns **kept** (absolute board-trace/datapath ceilings; the BIST also holds these at 160 ns) |

## 2. Build + timing (Task 2)

`TIDELINK_PHY_V2=1 make -C fpga build_pair_concurrent` → **both jobs PASS**, 22m15s.

| Target | WNS (setup) | WHS (functional, intra clk_out1) | Phantom hold |
|--------|-------------|----------------------------------|--------------|
| pynq-z2-pair-all | **+0.131 ns** (0 failing) | +0.053 ns (0 failing) | `clk_out1→pad_clk_tx_fwd` −26.8 ns / 8 ep; `pad_clk_rx` −7.9 ns / 8 ep |
| pynq-z2-pair-flip-all | **+0.268 ns** (0 failing) | +0.053 ns (0 failing) | similar |

* **WNS positive on both** — the closure that matters. The negative-WHS endpoints are
  the documented source-synchronous **phantom hold** paths: the `pad_tx[*]` launch vs
  its forwarded clock and the `pad_rx[*]` capture vs `pad_clk_rx`. The far die captures
  **mid-cell** (80 ns from either pad edge at 160 ns), so the same-edge hold check at
  the launch/capture pad is structurally meaningless — the calibrator absorbs it. v35
  carried the same phantom and ran on silicon.
* **Note for the next spin:** the BIST timing XDC false-paths this correctly with
  `set_false_path -hold -to [get_ports {pad_tx[*]}]`; the tidelink targets instead use
  a symmetric `set_output_delay -min`, which *requests* the meaningless hold check and
  is what produces the large −26.8 ns number. Cosmetic (does not affect the bitstream
  function) but worth porting the BIST's `-hold` false-path to silence it.
* No `.ltx` this build (no debug core inserted). Bring-up uses RO APB observability
  (0x44032108), not ILA, so `.ltx` is not required.

## 3. Bring-up sequence + evidence (Task 3)

Recipe = v35 "park-and-freeze" (`v36_round2.sh`), all registers base 0x44032000:
deploy both → `wr 0x44032160 = 0x55555555` (LOCK_THRESH 3→5) → coordinated arm
`slot0 0x1→(10ms)→0x3→(2ms)→0x1` → freeze `slot0=0x2`. Also tried the coordinated
**release** (`slot0 1→0`), which gave the cleanest result this build.

* **LOCK_THRESH=5 → instant bilateral S_HOLD park** (cstate=6 first try) — as v35.
* **PHY_ALIGN_ID (0x11C) = 0x50410100 on BOTH** — confirms the v36 PHY-V2 bitstream is
  correctly loaded and the register surface is live on both boards.
* **Best stable state (coordinated release):** die_b reaches **fcsm=4 LINK_IDLE in 1
  poll** and holds it:

```
die_b (z2_03, master): 0x108 = 0x85890091
  lk=0x91 cal=1 fcsm=4 cr=1 ck=1 full=1 won=1   # LINK_IDLE: decoded a's CR AND CRACK
die_a (z2_02, slave):  0x108 = 0x40020000
  lk=0x00 cal=0 fcsm=1 cr=0 ck=0 a2l=1 lost=1   # never decoded b's CR (B->A dead)
```

  (`full=1` on die_b = `fe_rx_is_full` — RX FIFO marks full because credits never return
  from die_a, whose link is down; the FC loop cannot complete one-directionally.)

* **M→S single-word data test** (master z2_02 0x44000000 ← `0x57A40001`; slave z2_03
  read 0x44010000): slave RX FIFO read **0x00000000 before and after — no crossing.**
  Expected: the data master here is die_a, whose own FCSM is at fcsm=1 (the reverse
  direction is dead), so it cannot emit FC data packets; bilateral LINK_IDLE is a
  precondition the B→A blocker prevents.

## 4. The blocker — now proven structural, not eye-margin

Direction **z2_03→z2_02 (flip-image TX → non-flip RX) never decodes the FCSM short
packet**, exactly as v35 §4. New this build: it is **fully deterministic** (not the v35
lottery), which is itself diagnostic — the eye is no longer the limiter.

Falsified at 6.25 MHz (die_a never reached cr=1 under any of these):
* 5× arm/freeze re-arm cycles (fresh per-lane latch each time) — identical every time.
* 3× whole-pair redeploy (fresh pad-mutual skew) — direction never flips, roles stable.
* LL_RX framer re-hunt ×4 (`slot0 0x2→0x3→0x2`).
* SWI_BIT_SLIP nudges 0x000000…0xFFFFFF (llv moves with slip, then drops at high slip —
  datapath responds, but cr never latches ⇒ the missing alignment is the **mod-16
  word-phase, OUTSIDE the 3-bit slip range**).
* Coordinated release rendezvous (wide eye) — die_b goes to fcsm=4, die_a stays cstate=2.
* Wlink CTRL DIS→FULL restart on die_a — no effect (0x208[3] Tier-2 masked, as v35).
* 12-sweep extended observation with periodic recal while die_b held a steady carrier.

**Classification (unchanged from v35, now confirmed rate-independent):** the 8-bit-periodic
training pattern locks blind to the mod-16 word/byte phase in the flip-TX direction;
WORD_PIN_AUTO (`WavD2DGpioRx` `wpa_match`, exact-16-bit) is compiled+enabled but is not
correcting this one direction in-system. First suspects (per the integration-readiness
list): the un-ported **CDC F2** item and/or the **flip-image TX launch-path** difference
vs the (validated, straight-ribbon, two-bitstream) BIST.

**Why I could not brute-force it from SW:** the manual word-pin override that would let
me walk die_a's capture window 0..15 to find the alignment (`word_pin_ovr` [27:24] /
`word_pin_auto_dis` [28] / `override_en` in `tidelink_phy_align_if`) is **hardwired off
in the v2 chiplet controller** (`axi_chiplet_controller.sv`: `apb_override_enable=1'b0`,
two instances). It is reachable only in the BIST register surface (`tidelink_phy_bist_regs`
BIT_SLIP_OVR), not the tidelink one — exactly as v35 §3.5 recorded. So the word-pin
cannot be moved without an RTL change + rebuild.

## 5. Remaining work (for v37)

1. **Expose a runtime word-pin override in the tidelink register surface** — wire
   `apb_override_enable` / `word_pin_ovr` to an APB reg (BIT_SLIP_OVR[28:24] equivalent)
   so the B→A capture window can be SW-walked 0..15 in-system. This is the single most
   likely path to closing B→A without a blind RTL guess, and turns the blocker from
   "needs a rebuild per attempt" into "one APB sweep."
2. **Port the CDC F2 fix** from the PHY repo finalization list and **diff the flip-all
   target's TX launch** (clk_tx_oddr / pad_clk_tx path on Y7-MRCC) vs the BIST flip
   image's TX launch — the BIST validated the straight ribbon with two *separate*
   bitstreams; the production pair uses one flip + one non-flip image, and the flip TX
   launch is the prime suspect for the mod-16 phase offset.
3. **ILA on z2_02**: post-deskew 128-bit bus + per-lane `word_pin` / comma-matcher
   activity in `WavD2DGpioRx` while z2_03 retries CR (the frozen park makes this a
   stable, repeatable capture). Build with `FPGA_INSERT_DEBUG_CORE=1`.
4. Cosmetic: port the BIST's `set_false_path -hold -to [get_ports {pad_tx[*]}]` into the
   pair timing XDCs to silence the −26.8 ns phantom WHS.

## 6. Verdict

The rate drop was the correct, evidence-backed move and it **fixed the eye-margin half**
(A→B is now deterministic full LINK_IDLE). It did **not** close the B→A direction,
because that blocker is a **word/byte-phase / flip-TX-launch structural issue**, not eye
margin — proven by its rate-independence and immunity to every runtime knob. **New-PHY
silicon status: unilateral LINK_IDLE (A→B fcsm=4, cr+ck), NOT bilateral, NO data
crossing.** The next lever is RTL (expose the word-pin override + CDC F2 + flip-TX diff),
not another SW recipe.
