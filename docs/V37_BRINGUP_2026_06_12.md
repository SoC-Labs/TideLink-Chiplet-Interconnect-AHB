## What is SOLVED

1. **The new serdes carries data on the real ribbon** — bilateral 8/8 lane
   lock, zero faults.
2. **Link rate** — 6.25 MHz (matching the silicon-validated BIST) is correct;
   v35's 25 MHz was 4× too fast for the exact-match word-pin on the marginal
   eye. (IDELAY, training pattern, and SYNC beacon were all ruled out as
   causes — v35 already matched the BIST on those.)
3. **Word-phase (the B→A blocker)** — the flip-image (z2_03) TX launches the
   16-bit word 5 positions offset from what the non-flip (z2_02) RX expects.
   The new word-pin override (`SWI_BIT_SLIP_LO[27:24]=pin`, `[28]=auto-disable`,
   commit `69a9a8d`) **proves it**: sweeping word_pin 0..15 on z2_02's RX,
   only **word_pin=5** yields `lk=0xff` (all 8 lanes), word_pin=6 → `0xf1`,
   every other value → `0x00`. A single, deterministic word window closes
   B→A's lane alignment.
4. **Autoneg / roles** — the v34-proven autonomy stack resolves cleanly on
   v37: z2_02 → slave (`NEGO_STATUS lost=1`), z2_03 → master (`won=1`).

## The remaining blocker (precisely located)

With word_pin=5 held and the link left to the POR autonomy FSM, **both
calibrators sit in `S_SWEEP` (OBS_CAL `0x44032198[3:0] = 2`) indefinitely
(>12 s)** and never reach `S_DONE` / `cal_done`. A full slip×phase sweep
completes in ~130 ms at 6.25 MHz, so this is not a slow sweep — it is a
**mutual-sweep stall**: both dies sweep simultaneously, so neither presents a
stable training reference for the other to lock against, on the marginal B→A
direction.

The V1 calibrator solved this with `S_HOLD` (the first die to lock holds
`training_mode` high while its peer converges) plus the SW "park-and-freeze"
coordinated arm/release recipe. The V2 always-on FSM (deps/tidelink-phy)
has an `S_HOLD` state but is not reaching it here — this is calibrator-internal
coordination behaviour, owned by the PHY repo.

## Evidence (representative, word_pin=5 held, hands-off autonomy)

```
t=1s  A[ lk=00 cal=0 fcsm=1 cr=0 | calst=2(S_SWEEP) | nego=5 lost=1 ]   (slave)
      B[ lk=80 cal=0 fcsm=1 cr=0 | calst=2(S_SWEEP) | nego=0 won=1  ]   (master)
   ... both pinned at calst=2 through t=12s, lk flickering as the sweep moves ...
```
With training held steady (`slot0=0x1`) instead of swept, the same word_pin=5
gives z2_02 `lk=0xff` — confirming the alignment is correct; only the
autonomous sweep coordination fails to capitalise on it.

## Next steps (recommended order)

1. **Calibrator sweep-coordination fix (PHY repo, deps/tidelink-phy)** — make
   the V2 calibrator reach `S_HOLD` on partial/one-sided lock so the peer can
   converge against a held reference (the V1 mechanism, ported into the
   always-on FSM). This is the autonomous fix and the likely single blocker
   between here and bilateral link. Coordinate with the calibrator-rewrite
   owner.
2. **Per-board POR word-pin default** — seed the non-flip RX's `WORD_PIN_AUTO`
   (or the manual override) with a POR default of 5 so word-alignment is
   correct from reset without SW, removing word_pin from the bring-up path.
3. **ILA on z2_02's calibrator + post-deskew bus** — confirm the S_SWEEP exit
   condition / dwell-lock behaviour directly; the frozen-but-word-aligned
   state (word_pin=5, steady training) makes this a stable capture.
4. Once bilateral `fcsm=4` is reached: the M→S data test (`0x57A40001` →
   master `0x44000000` → slave `0x44010000`) — the hardware-validatable
   milestone.
