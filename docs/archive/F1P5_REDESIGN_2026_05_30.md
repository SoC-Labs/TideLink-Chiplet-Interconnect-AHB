# F-1.5 Redesign — Avoiding the Build #6 PS-Wedge Hazard

**Date:** 2026-05-30
**Branch:** `fix/fcsm-l7-wedge-watchdog` @ `cbcd4ef` (F-1 only, F-1.5 reverted)
**Author:** dispatched designer (read-only RTL pass; doc only)
**Scope:** redesign the state-7 → state-4 escape mechanism that the reverted commit `09cc0ec` attempted, in a way that cannot reproduce the build #6 catastrophic PS kernel-hang.

---

## 1. Executive summary

The reverted F-1.5 added an `else if (socl_l7_wdog_force_clear && state == 3'h7) state <= 3'h4;` clause *between* the synchronous-reset arm and the existing four `else if` next-state arms inside the FCSM's `state` always-block at line 834 of `src/rtl/local_overrides/WlinkGenericFCSM_6.v`. The block remained the single procedural driver of `state`, but the priority chain it produced is materially different from what the surrounding combinational `_GEN_*` network expects: most of the FCSM's *downstream* outputs (`ne_rx_ptr`, `last_ack_pkt_sent`, `count`, `link_data`, `sop`, prepend bus) are computed from `_GEN_115 = auto_tx_out_advance ? 3'h4 : state` and from `state == 3'h7` predicates that the original always-block was guaranteed to commit *atomically* with `state`. Forcing `state <= 3'h4` without also driving the partner registers leaves the FCSM in a structurally impossible micro-architecture state — pointer regs say "mid-NACK, awaiting auto_tx_out_advance", state says "LINK_IDLE, accept new packets". On HW that translates into an indefinitely held `tl_fc_a2l_ready=0` (confirmed by E's returner trace, §3) and a `pready=0` that stalls the AHB write path. PS Linux blocks in `mmap` write to `/dev/mem`, kernel watchdog cannot recover, board needs power-cycle.

**Recommended redesign: Option D (companion-FSM single-driver override) layered with a partner-register restore.** Concretely, build a small 2-state companion FSM in a **new** always-block that drives a `socl_l7_state_override_valid_r` strobe; merge into the *next-state expression* via a single combinational override at `_GEN_181` so the existing `state` always-block remains the *sole* procedural driver; and *on the same cycle*, drive a synchronous restore of `ne_rx_ptr`, `last_ack_pkt_sent`, `count`, `sop`, and the prepend mux selects from a pre-state-7 shadow captured by F-1's pointer-shadow regs.

## 2. Failure-mode forensic — why build #6 hung the PS

### 2.1 What the reverted patch added (verbatim)

```verilog
always @(posedge io_tx_clk or posedge io_tx_reset) begin
  if (io_tx_reset) begin
    state <= 3'h0;
  end else if (socl_l7_wdog_force_clear && state == 3'h7) begin
    state <= 3'h4;                       // F-1.5 (reverted)
  end else if (_fe_rx_ptr_in_T) begin
    state <= 3'h0;
  end else if (_ack_seen_before_T) begin
    ...
```

### 2.2 Hypothesised silicon mechanism (ranked)

**H-A (DOMINANT): partner-register desync, not Vivado FF-inference.** The single-driver invariant *is* satisfied by the reverted code: `state` has exactly one always-block, posedge `io_tx_clk` / `io_tx_reset`, no blocking assigns. Vivado will infer an FDCE/FDPE cleanly. The hazard is at the **micro-architecture** layer: lines 511-549 of the override expose dozens of `_GEN_*` wires that compute the *partner* state of `ne_rx_ptr`, `last_ack_pkt_sent`, `count`, `sop`, `link_data`, `data_id`, `word_count`, `send_ack_req` as a function of `auto_tx_out_advance` AND the *current* value of `state`. The existing always-block transitions out of state 7 only via `_GEN_115 = auto_tx_out_advance ? 3'h4 : state`, which is precisely the gate that *also* feeds `_GEN_104..113` (the partner registers' next-state). When the priority clause force-jumps `state` to 4 with `auto_tx_out_advance = 0`, **none of those partner regs latch their state-4 values**. The FCSM resumes from state 4 with TX pointers rewound to `last_good_pkt_from_rx` (set on state-7 entry by `_GEN_152` per E's trace, §3.1), with `sop=0`, with `link_data=0`, with `data_id=swi_nack_id`. The first real packet the FCSM tries to emit from state 4 sees `link_data=0`, `sop=0` — the LL_TX layer sees a malformed packet, never asserts `auto_tx_out_advance`, never returns `tl_fc_a2l_ready=1`. The skid stays full, returner stays in `ST_DATA_PHASE`, `rtn_hready=0` indefinitely.

The downstream consequence is the AHB stall: `tidelink_fc_adapter.sv:245` ties `rtn_hready = rtn_pending_r ? skid_can_accept : 1'b1`. The doorbell APB ring on master triggers the returner; the returner asks the FC adapter to commit; `skid_can_accept` returns 0; the AHB master holds `htrans=NONSEQ` and the slave (the FC adapter as AHB-slave to the returner) holds `hready_out=0`. SmartConnect/AXI-Lite-to-AHB bridge stalls the AXI write. The PS write to `/dev/mem` blocks in kernel mode with the AXI-Lite waiting on `bvalid`. Kernel watchdog can't preempt a stuck `mmap` writer.

**H-B (secondary, lower confidence): clock-enable inference change.** With four `else if` arms, Vivado synthesises `state` as an FDCE with a 4-way CE mux. Adding a fifth higher-priority arm tied to `socl_l7_wdog_force_clear` (a near-static signal that asserts and stays high) may have prompted Vivado to extract `socl_l7_wdog_force_clear` as the FDCE's clock-enable input — turning the FF into one that is *only* clocked when the watchdog says so, suppressing the other transitions. The synthesis log would show a SYNTH-6 message ("Clock enable inferred"). We do not have the build #6 log to confirm; this is a known Vivado quirk on priority chains where one arm is a near-constant. Mitigation in the redesign is to **not** introduce any new always-block-internal priority clauses on the `state` FF.

**H-C (low): combinational glitch at state==3'h7 falling edge.** The reverted code transitions `state` 7→4 on the rising edge of `socl_l7_wdog_force_clear` (one cycle after the counter saturates). Multiple `_GEN_*` wires include `state == 3'h7` predicates; their combinational outputs change in the same cycle the state FF transitions, and any consumer that latches them on the *same* edge (e.g. `send_nack_req` clearing logic that we already have) may sample the post-transition value. This is a same-cycle data dependency that compiles fine in sim but is hold-time sensitive on silicon. Less likely to be the *primary* cause of a hard wedge, but contributes to non-determinism.

### 2.3 Why the cocotb test missed it

`test_post_watchdog_doorbell_delivery` uses `cocotb.handle.Force(state=7, send_nack_req=1)` followed by `Release()`. After release, the simulator re-runs the always-block's RHS with the *current* values of `_GEN_*` — which were also affected by the Forces. The test does not exercise the natural state-7 entry path that commits `_GEN_152..158` to the partner registers, so the partner-register desync the silicon experiences is invisible. The test passes because the sim FCSM has no upstream pointer state to be wrong with.

This is the build #6 lesson H captures in §5 of the sim repro doc: *Force-injection is a Verilog-procedural construct; the silicon failure is a micro-architectural invariant violation that Force-injection bypasses.*

## 3. New design — Option D (single-driver companion FSM)

### 3.1 Specification

Three changes, none of which touch the existing `state` always-block's body:

**(a)** New 2-state companion FSM in a *new* always-block, drives a single-cycle strobe `socl_l7_override_pulse` and a 3-bit `socl_l7_override_target`.

**(b)** New shadow registers `socl_l7_pre_l7_ne_rx_ptr_r`, `..._last_ack_pkt_sent_r`, `..._count_r`, capturing the values these regs held the cycle *before* `state` transitioned to 7. (E's trace §5 fix-path-A independently arrived at the same shadow-register conclusion.)

**(c)** Single combinational override at the *next-state expression* for `state`, and matching synchronous restores in the existing partner-reg always-blocks gated by `socl_l7_override_pulse`. Crucially the override is wired into `_GEN_181`'s upstream MUX, **not** as a new priority clause in the `state` always-block.

### 3.2 Verilog sketch (commented)

```verilog
// -------------------------------------------------------------------------
// SoC Labs F-1.5 (REDESIGN, post-build-#6 hazard)
//
// Companion FSM that issues a 1-cycle "state-7 escape" pulse when:
//   (i)  socl_l7_wdog_force_clear is asserted   (F-1 watchdog has fired)
//   (ii) the FCSM has actually been in state 7  (avoid spurious pulses)
//   (iii) we have not already issued the override since the last reset
//         (one-shot — the watchdog can re-fire, but the override is
//          single-use per reset cycle; if state 7 re-occurs after a real
//          link event, the unmodified RTL handles it).
//
// The pulse is consumed combinationally by the override-mux feeding the
// EXISTING state always-block.  Critically:
//   - The state FF still has exactly one procedural driver (the
//     pre-existing always-block at line 834).
//   - No new always-block writes `state`.
//   - The override pulse is also fanned into the partner-register
//     always-blocks (ne_rx_ptr, last_ack_pkt_sent, count, sop, link_data,
//     data_id, word_count) to synchronously restore them from shadows
//     captured pre-state-7-entry.  This avoids the H-A desync that hung
//     build #6.
// -------------------------------------------------------------------------

// ---- (a) companion FSM ----------------------------------------------------
reg        socl_l7_override_armed_r;   // 1 once we've ever fired the override
reg        socl_l7_override_pulse_r;   // 1-cycle strobe to override mux
wire       socl_l7_override_arm_cond =
             socl_l7_wdog_force_clear & (state == 3'h7)
             & ~socl_l7_override_armed_r;

always @(posedge io_tx_clk or posedge io_tx_reset) begin
  if (io_tx_reset) begin
    socl_l7_override_armed_r <= 1'b0;
    socl_l7_override_pulse_r <= 1'b0;
  end else begin
    socl_l7_override_pulse_r <= socl_l7_override_arm_cond;
    if (socl_l7_override_arm_cond) socl_l7_override_armed_r <= 1'b1;
  end
end

// ---- (b) shadow regs captured the cycle BEFORE state-7 entry --------------
// Trigger: the cycle whose next state will be 7 (i.e. send_nack_req is being
// latched).  We use the existing _GEN_76 / _GEN_100 / _GEN_127 family
// predicates that drive 3'h7 — sampling them in a new always-block keeps the
// existing block untouched.
wire socl_l7_next_state_is_7 =
       (_GEN_76 == 3'h7) | (_GEN_100 == 3'h7) | (_GEN_127 == 3'h7);

reg [7:0]  socl_l7_shadow_ne_rx_ptr_r;
reg [7:0]  socl_l7_shadow_last_ack_pkt_r;
reg [7:0]  socl_l7_shadow_count_r;
reg        socl_l7_shadow_sop_r;
reg [55:0] socl_l7_shadow_link_data_r;
reg [7:0]  socl_l7_shadow_data_id_r;
reg [15:0] socl_l7_shadow_word_count_r;

always @(posedge io_tx_clk or posedge io_tx_reset) begin
  if (io_tx_reset) begin
    socl_l7_shadow_ne_rx_ptr_r    <= 8'h0;
    socl_l7_shadow_last_ack_pkt_r <= 8'h0;
    socl_l7_shadow_count_r        <= 8'h0;
    socl_l7_shadow_sop_r          <= 1'b0;
    socl_l7_shadow_link_data_r    <= 56'h0;
    socl_l7_shadow_data_id_r      <= 8'h0;
    socl_l7_shadow_word_count_r   <= 16'h0;
  end else if ((state != 3'h7) & socl_l7_next_state_is_7) begin
    socl_l7_shadow_ne_rx_ptr_r    <= ne_rx_ptr;
    socl_l7_shadow_last_ack_pkt_r <= last_ack_pkt_sent;
    socl_l7_shadow_count_r        <= count;
    socl_l7_shadow_sop_r          <= sop;
    socl_l7_shadow_link_data_r    <= link_data;
    socl_l7_shadow_data_id_r      <= data_id;
    socl_l7_shadow_word_count_r   <= word_count;
  end
end

// ---- (c) override the next-state input to _GEN_181 ------------------------
// Original:    state <= _GEN_181;   (in the existing always-block)
// New:         _GEN_181 source is wrapped through a 2:1 mux that picks 3'h4
//              when socl_l7_override_pulse_r is high.
// SINGLE-DRIVER pattern: we redefine the wire _GEN_181 itself (or shadow it
// with a new wire and rename consumers — the cleanest patch is a new wire).

wire [2:0] _GEN_181_post_l7 = socl_l7_override_pulse_r ? 3'h4 : _GEN_181_orig;

// Then change line 850 of the existing always-block from:
//     state <= _GEN_181;
// to:
//     state <= _GEN_181_post_l7;
// AND rename the pre-existing `wire [2:0] _GEN_181 = ...` to
// `wire [2:0] _GEN_181_orig = ...`.   That is the only edit to lines 590-850
// of the file — purely combinational, single procedural driver preserved.

// ---- (d) partner-register synchronous restores ----------------------------
// Wrap the existing ne_rx_ptr / last_ack_pkt_sent / count / sop / link_data
// / data_id / word_count always-blocks with a top-priority restore arm.
// Pattern (illustrated for ne_rx_ptr):
//
// always @(posedge io_tx_clk or posedge io_tx_reset) begin
//   if (io_tx_reset)                       ne_rx_ptr <= 8'h0;
//   else if (socl_l7_override_pulse_r)     ne_rx_ptr <= socl_l7_shadow_ne_rx_ptr_r;  // NEW
//   else if (<existing reset-zero clause>) ne_rx_ptr <= 8'h0;
//   else if (<existing update clause>)     ne_rx_ptr <= <existing next val>;
// end
//
// Same pattern applied uniformly to: last_ack_pkt_sent, count, sop,
// link_data, data_id, word_count.  Each remains in its own always-block
// (single-driver), with one new priority arm inserted DIRECTLY AFTER the
// reset arm.  The override pulse is a single io_tx_clk-domain register, so
// no CDC.
```

### 3.3 Why this avoids each build-#6 hypothesis

- **H-A (partner desync):** partner regs are co-restored in the same cycle as the state override. The FCSM resumes from state 4 with a coherent micro-arch snapshot from before the state-7 detour.
- **H-B (CE inference):** the `state` always-block's body is unchanged. The new override is a wire, not a new arm. Vivado FF inference is bit-identical to F-1-alone.
- **H-C (combinational glitch):** the override is a *registered* pulse (`socl_l7_override_pulse_r`), not a combinational fan-out of `socl_l7_wdog_force_clear`. It deasserts after 1 cycle. Downstream consumers see a clean single-cycle transition.

## 4. Sim test plan — catch the hazard BEFORE next HW build

Three layers, total wall budget ~12 min, all must pass before queuing build #7:

**(L1) Replace Force-injection with natural-bringup trigger.** New cocotb test `test_post_watchdog_natural_bringup.py` (sibling of the existing test) that:
   - lets POR + role_lock + Phase-1 cal_done all complete naturally
   - injects an `isNotExpPacket` glitch on the master RX path by writing a synthetic packet into the L2A FIFO via DPI tap (no Force on `state` or `send_nack_req`)
   - polls `socl_l7_wdog_force_clear`, then asserts state actually transitions to 4
   - rings doorbells and verifies `slave.DOORBELL_RESP_ACC` increments
   This exposes the partner-register desync because the FCSM enters state 7 naturally, latching `_GEN_152..158` into the partner regs.

**(L2) SVA assertions on partner-register coherence.** Add bound assertions in a new `src/rtl/sva/fcsm_state_coherence_sva.sv`:
```systemverilog
property p_state4_after_l7_partner_coherent;
  @(posedge io_tx_clk) disable iff (io_tx_reset)
    $rose(socl_l7_override_pulse_r) |=>
      ((state == 3'h4) &&
       (ne_rx_ptr == $past(socl_l7_shadow_ne_rx_ptr_r)) &&
       (sop == $past(socl_l7_shadow_sop_r)) &&
       (link_data == $past(socl_l7_shadow_link_data_r)));

assert property (p_state4_after_l7_partner_coherent)
```

Hook into `cocotb/tidelink_top_pair` via VCS `-assert` flag (already wired for the calibrator SVA suite per CLAUDE.md notes).

**(L3) Vivado synth-only sanity run.** Add a make target `syn-check-fcsm-override` that runs `synth_design` only (no place/route, ~3 min) and greps the log for:
   - `SYNTH-6` (clock-enable inferred) — fail if the FCSM `state` FF has CE driven by anything other than the original arms
   - `Synth 8-327` (inferred latch) — fail any
   - `Synth 8-3331` (design has unconnected port) on the new override wires
   - `Synth 8-6014` (resolved multi-driven net) — fail any on FCSM internals

Output of L3 archived as `syn/fpga/fcsm_override_synth_check.log` so the CI can diff against a known-good baseline.

## 5. ASIC-portability notes

The redesign uses **only** these constructs, all of which are clean in Fusion Compiler / DC and any standard-cell library:
- `always @(posedge clk or posedge async_reset)` — maps to FDC/FDPC.
- 2:1 muxes on next-state wires — maps to MX2 / standard mux cells.
- No `force`/`release`, no `defparam`, no `disable`, no `wait`, no `initial`.
- All non-blocking assignments inside clocked blocks.
- No new combinational loops (override pulse is a register output; consumers are next-state wires already in the existing fanout cone).
- New shadow registers add ~80 FFs to the FCSM. At TSMC 65nm typical density this is <0.02 mm² — negligible.

One ASIC-specific note: in Fusion Compiler, the new shadow-register capture clause `(state != 3'h7) & socl_l7_next_state_is_7` is a clock-enable inference candidate. This is *desirable* on ASIC (saves power) and synthesises identically in Vivado. No change required between FPGA and ASIC flows.

The SVA in §4 L2 must be wrapped in `\`ifndef SYNTHESIS` / `\`ifdef FORMAL` to keep it out of the FC synthesis flow. The existing project convention (see `src/rtl/calibrator/*_sva.sv`) already does this.

## 7. Risks NOT addressed by this redesign

- **Returner has no upper bound on `ST_DATA_PHASE` time.** Even with a coherent F-1.5, a future class of bug (calibrator regression, IDELAY drift, ESD-induced bit flip on a credit packet) can still wedge `rtn_hready` indefinitely. E's fix-path B (returner-side timeout, `BUILD5_RETURNER_TRACE_2026_05_30.md` §5) is orthogonal and should land in parallel. This redesign deliberately keeps the change radius small — returner robustness is its own work-item.
- **No SW escape hatch (F-5 deferred).** If F-1.5 itself misfires post-silicon, SW cannot recover the link without a full FPGA reset. F-5 (APB-writable FCSM soft-reset bit) remains the v1.1 backstop.
- **One-shot override only.** `socl_l7_override_armed_r` permanently latches after the first override fire, so a *second* transient state-7 wedge in the same reset cycle would not be recovered. The design assumption (consistent with F-1's `socl_l7_real_crc_seen` semantics) is that the bringup-glitch window is single-shot and steady-state link operation is correct. If long-run HW shows repeated wedges, the one-shot needs revisiting — but the current evidence (BUILD5 §3 multi-deploy table) shows the wedge is exactly a per-reset-cycle event.
- **No fault on shadow-capture miss.** If the shadow regs never captured (e.g. state transitioned to 7 *immediately* after reset, before the first non-7 → 7 transition), the override would restore zeros. This matches reset-default and is safe, but is not detected as an anomaly. An optional `socl_l7_shadow_valid_r` qualifier could be added if HW debug shows unexpected post-override behaviour.
- **SVA L2 is sim-only.** The coherence assertion catches the build-#6 class in sim; it does *not* run on silicon. A persistent hardware monitor (counter of override-pulse events, exposed via APB) is a v1.1 add.
- **Vivado version drift.** L3 synth-only check is pinned to Vivado 2024.1; a future tool upgrade could change FF inference. The CI archive should diff against the baseline log on every Vivado upgrade.
