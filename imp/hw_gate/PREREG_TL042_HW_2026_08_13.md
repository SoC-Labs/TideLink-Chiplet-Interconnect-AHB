# Pre-registered predictions — TL-042 HW validation (2026-08-13)

Written BEFORE the bitstream finished building and BEFORE any deploy, so the
result cannot be rationalised after the fact. Same discipline as the two ILA
rounds earlier today.

## What is being tested

TL-042: `wr_hold_r` can hold `ahb_sub_hreadyout` low forever. Measured on die_a
(round-2 ILA, 43 probes, 4097 samples, plus an n=2 confirm): at the wedge
`wr_hold_r`=1 on all samples, `wr_hold_clr` never asserts, override-mux ranks 1-4
are all false, so rank-5 `wr_hold_r` is the SOLE term driving `hreadyout` low —
with `sub_aw_accept`=0, `sub_wr_os_ctr`=0, `synth_b_pending`=0.

Self-sustaining loop: hold -> hreadyout low -> no AW reaches `s_axi` -> ctr stays
0 -> the pre-existing synth-B arm (gated on `ctr != 0`) can never fire ->
`wr_hold_clr` (W-last | synth_b_pending) never asserts -> hold persists.

## The fix under test

`wr_hold_stuck_ctr_r` ages the state (`wr_hold_r` high AND `ctr == 0`) and widens
`sub_wr_stuck_fire` at 2**16 hclk, so the EXISTING synth-B path releases the hold.
`synth_b_holdclr_only_r` records that the arm came from this new path and
suppresses `s_axi_bvalid`, so no synthetic B is presented to XHB500 for a write it
never issued.

No new term was added to the `:1909` hreadyout mux — that mux has already
produced three guard failures.

## PREDICTIONS (falsifiable, recorded in advance)

**P1 — PRIMARY.** The errinject AW byte-0 case that wedged die_a **4/4** pre-fix
will NOT wedge. The escape fires at 2**16 hclk ~= 0.65 ms @100 MHz, far below any
host-visible timeout, so from the PS side the write should simply complete.
- Confirms: die_a survives the inject, resume-stream words land on die_b.
- REFUTES THE FIX: die_a still wedges 4/4. If so, `wr_hold_r` was not the only
  thing holding the bus on this build, or the escape does not fire in silicon.

**P2 — NO NEW HARM.** The clean (no-inject) path must be unchanged: the byte-exact
crossing that scored 128/128 on 08-09 must still score 128/128. The fix cannot
fire on a healthy write, because an accepted AW makes `ctr != 0` and resets the
counter within a handful of cycles.
- REFUTES: any drop in the clean-path score. That would mean the new arm fires on
  normal backpressure, which the RTL argues is impossible with ~4 orders of margin.

**P3 — NO SPURIOUS B.** No AXI protocol complaint or bridge misbehaviour
attributable to a synthetic B with nothing outstanding. Sim shows `bvalid_seen=0`
across the escape; silicon should agree.
- REFUTES: bridge response-tracking corruption after an escape.

## Explicitly NOT claimed

End-to-end service resumption is NOT proven in sim. The only way to synthesise the
deadlock state in the TB is to freeze `s_axi_awready/wready`, and sustaining that
for the full timeout wedges XHB500 itself — measured: after release, `hreadyout`
stays low with all six ranks reading 0, i.e. the residual is the bridge's own raw
output at the mux fallthrough, collateral from the entry mechanism. That is why P1
is a BENCH result and cannot be inferred from the passing sim test.

## Sim evidence backing this (already measured)

Non-vacuity A/B, both arms md5-pinned, `test_wr_hold_stuck_escapes_tl042`:
- pristine RTL: **FAIL** — "wr_hold_r STILL HIGH after 90k hclk"
- fixed RTL: **PASS** — escapes at cycle 65518, all six ranks clear, `bvalid_seen=0`

`sim_gate_axi_datanode_recovery` exit 0, `sim_gate_axi_datanode_gaps` exit 0, both
writehold tests pass (TL-002's original invariant included).
