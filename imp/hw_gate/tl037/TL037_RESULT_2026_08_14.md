# TL-037 — RESULT: **REAL, STILL OPEN, AND IT IS AN RTL DEFECT — NOT AN FPGA-ONLY BD GAP**

Branch `integ/tidelink-consolidated-2026-08-07`, HEAD `e21e274`. Simulation and
static analysis only — no board touched, nothing committed, no vendor IP
modified, **no tracked file changed**.

**Headline.** The registry's factual claim is true — there is no AXI Firewall /
AXI Timeout IP anywhere in the eth-chiplet block design. But its `root_cause`
("*Not an RTL defect: an integration/survivability gap*") and its caveat
("*FPGA-ONLY (PL block design). Does NOT help the ASIC*") are **wrong**.

`src/rtl/tidelink_top.sv` already contains the timeout TL-037 asks for — the
per-beat `sub_stall_ctr_r` backstop, built 2026-07-06 for exactly this failure.
It is **dead for the case it was built for**. Both of its ERROR fire sites are
gated on `sub_rd_os_r`, and the synth-B write drain is gated on
`sub_wr_os_ctr` — so a transfer that stalls **before its AW/AR ever reaches
s_axi** is covered by nothing at all. The timer runs to expiry, resets itself,
and fires *nothing*, forever. `ahb_sub_hreadyout` stays low, the PS store/load
never returns, and recovery is a power-on reset.

That is netlist-affecting and applies to the **ASIC as much as the FPGA** — and
it is a one-condition fix, sim-proven below, with a non-vacuous A/B in both
directions and on the ASIC-mirror config.

The state is not exotic. It is where the port lands **immediately after the
existing read backstop successfully rescues one transaction** — so on a wedged
link you get exactly *one* recoverable bus error, and every access after it
hangs unbounded.

## 1. What TL-037 actually is — verified against the design, not the registry

### 1a. TRUE and still open: there is no firewall in the block design

`grep -rn -i 'axi_firewall|axi_timeout|firewall'` over the whole repo returns
**zero** instantiations — only prose in `docs/` and the registry itself. The
eth-chiplet PS path is, from
`fpga/targets/kr260-eth-chiplet/tidelink_design.tcl:127-133`:

```
PS M_AXI_HPM0 -> xilinx.com:ip:smartconnect:1.0 (axi_smc)
              -> xilinx.com:ip:axi_ahblite_bridge:3.0 (axi_ahb_eth_ss)
              -> soclabs.org:user:nanosoc_eth_chiplet_vivado_wrapper:1.0
              -> nanosoc SoC AHB -> tidelink `ahb_sub`
```

No terminator anywhere on it. **This half of the registry entry is not stale.**

### 1b. WRONG: "not an RTL defect" / "FPGA-only"

`src/rtl/tidelink_top.sv` has two backstops on the PS-facing `ahb_sub` port, and
a third mechanism for writes. Their fire conditions are:

| mechanism | line | fires only when |
|---|---|---|
| per-beat stall ERROR | `:1636-1645` | `sub_stall_expired` **and `sub_rd_os_r`** |
| I5 outstanding ERROR | `:1669-1696` | `sub_osr_expired` **and `sub_rd_os_r`** (timer itself only *runs* while `sub_axi_outstanding`) |
| synth-B write drain | `:1856` (`sub_wr_stuck_fire`) | either expiry **and `sub_wr_os_ctr != 0`** |

`sub_rd_os_r` is set by `sub_ar_accept = s_axi_arvalid & s_axi_arready`, and
`sub_wr_os_ctr` by `sub_aw_accept`. **Every recovery on this port therefore
requires the transaction to have already been accepted onto s_axi.**

XHB500 holds `hreadyout` low long before that happens
(`..._core_resp.sv:181-183`, `RESP_FSM_SEQ_NSEQ`: `if (~address_readyout)
hreadyout = 1'b0;`), and `pause_addr_submit`
(`..._core_addr.sv:151-154`) blocks a read on

```
~cntrl_1_out.hwrite & (~ready_for_read || hazard_read)
```

with `ready_for_read = (read_counter==5'd0 | (r_done & read_counter==5'd1))`
(`core_resp.sv:233`) and `read_counter` decremented **only** by `r_done`
(`core_resp.sv:115-123`).

So a read whose R is permanently lost parks `read_counter` at 1 **forever** —
and the tidelink read backstop makes this worse, not better: it retires the
master with a legal AHB ERROR and clears `sub_rd_os_r`, but it cannot make the
far side return the R, so XHB500 never re-idles. From that moment every
subsequent peer access — **read or write**, because the single response FSM is
parked — is paused with `sub_rd_os_r == 0` **and** `sub_wr_os_ctr == 0`. The
per-beat stall timer counts to expiry into a dead gate.

`src/rtl/tidelink_top.sv` is at `flists/tidelink_top_full_asic_v2.flist:409`.
**The defect is in the tapeout netlist.**

gated on a bit that is 0.

Two honest caveats on this capture:

- It is the **pre-F-1** build: `err1` fires for a *write* (`wr_os`=1), which
  post-F-1 is synth-B's job. That changes which mechanism retires the *first*
  transaction; it does not change the post-window state, which is what matters
  here — and the sim below reproduces the same dead gate on today's RTL.
- The capture is 4096 samples deep and the shipping window is 2^16, so the
  capture **cannot show the expiry itself**. It proves the *state*; the RTL
  proves what the expiry does in that state (nothing); the sim below closes the
  last step by shortening the window so the expiry is reachable.

**Refinement of the 2026-08-02 verdict.** That session concluded "I5 FIRES
PERFECTLY; the HRESP=ERROR does NOT reach the PS", and from there that the fix
must be an upstream firewall. The capture shows a textbook, complete 2-cycle
AHB ERROR at the port (win 256-257) — whether it propagated upstream is *not
observable from this capture*. There is a simpler sufficient explanation for the
PS death that **is** observable: the PS's next access hit the dead gate and hung
forever with no error at all. That does not refute the upstream hypothesis (I
cannot see upstream), but it removes the need for it, and unlike it, it is
fixable in RTL and on the ASIC.

## 3. The fix

`imp/hw_gate/tl037/tl037_fix_ahb_sub_terminal_timeout.patch`
— **patch file only**; `git apply --check` verified; nothing applied, nothing
committed. 106 lines, of which the functional change is **6 lines**: one 1-bit
register, its 4-line driver, and one `else if`.

### 3a. The mechanism

```systemverilog
            end else if (sub_stall_expired) begin
                sub_stall_ctr_r <= '0;
                if (sub_rd_os_r) sub_err1_r <= 1'b1;   // unchanged
+               else if (sub_mst_dphase_r && (sub_wr_os_ctr == 3'd0)
+                                         && !synth_b_pending)
+                   sub_err1_r <= 1'b1;   // TL-037: terminal timeout
            end else begin
```

with the new predicate driven after the `ahb_sub_hreadyout` assign:

```systemverilog
+   always_ff @(posedge hclk or negedge hresetn) begin
+       if (!hresetn)                            sub_mst_dphase_r <= 1'b0;
+       else if (ext_is_nonseq && !pipe_valid_r) sub_mst_dphase_r <= 1'b1;
+       else if (ahb_sub_hreadyout)              sub_mst_dphase_r <= 1'b0;
+   end
```

`sub_mst_dphase_r` means *"the wrapper has taken a transfer from the master and
has not answered it yet"*. It is SET by the same qualifier the address pipeline
(`:1596`) and `wr_hold_r` (`:1846`) already use, and CLEARED the cycle
`ahb_sub_hreadyout` goes high — which on this port is exactly the cycle the
master is answered, because the fill term, `rd_pipe_r` and `wr_hold_r` each hold
hreadyout low across the whole of a read's and a write's data phase.

### 3b. Why each guard is there

- **`sub_mst_dphase_r`** — this is **F-1's requirement, stated correctly**. F-1
  (2026-08-02) barred an ERROR landing on an idle bus, and implemented that by
  gating on `sub_rd_os_r` — which also disabled the one case the per-beat stall
  backstop existed for. The right predicate is "is the master waiting?", not "is
  something outstanding on s_axi?". On an idle bus `sub_mst_dphase_r` is 0 and
  nothing fires, so the F-1 property is preserved — and asserted (see §4).
- **`sub_wr_os_ctr == 0`** — a stuck write is owned by synth-B, which keys on
  this *same* expiry. Never double-drive it (F-1).
- **`!synth_b_pending`** — the master-facing ERROR is masked by
  `& ~synth_b_pending` at the two output assigns, so firing into a drain would
  reproduce **N1** (an ERROR fired, masked, and never re-fired).
- The **`else`** keeps the pre-existing `sub_rd_os_r` path bit-identical. **The
  only behaviour change is in a case that previously did nothing at all.**

### 3c. What it deliberately does NOT do

It asserts nothing and clears nothing but its own one-shot. It does **not**
touch `synth_b_pending` (a LEVEL that is a term of `wr_hold_clr` — asserting it
disables the TL-002 peer-write hold, which is exactly why the TL-042 candidate
was rejected on hardware), nor `sub_rd_os_r`, `sub_wr_os_ctr`, `wr_hold_r`, nor
either output mux. No new sticky state.

**No comb loop** (the load-bearing wrapper invariant, `cb33c9f`): the new
register's inputs are `ext_is_nonseq` (hsel/htrans only), `pipe_valid_r` (reg)
and `ahb_sub_hreadyout` (already free of any `ahb_sub_hready` dependence), and
it feeds only the registered `sub_err1_r`. `ahb_sub_hreadyout` gains no
combinational dependence on `ahb_sub_hready`.

**Cost:** recovery is deferred to the end of the stall window that is already
running — 2^16 hclk ≈ 2.6 ms at 25 MHz — bounded, compared against never.

### The A/B is not vacuous by construction

Each primary test refuses to pass unless the scenario was genuinely built. It
asserts, and fails as **"CANNOT CONSTRUCT / DOWNGRADED — THIS IS NOT A PASS"**
if absent:

- trip 1 really was rescued by the existing backstop (`class=ERROR`);
- the dead-gate state was held for at least half a stall window;
- **the stall timer actually EXPIRED while in the dead-gate state**
  (`deadgate_at_expiry >= 1`) — the precise predicate;
- synth-B did **not** fire (i.e. this is not the already-covered case).

In arm B the scenario is entered **identically** — `first_deadgate=2`,
`deadgate_at_expiry=1`, `synthb_rises=0` — so the fix does not dodge the
scenario, it survives it. The *only* difference between FAIL and PASS is the
verdict.

```
B, READ  trip2: class=ERROR  deadgate_run_max=8093  stall_expiries=1
                deadgate_at_expiry=1  err1_rises=1  err2_cycles=1
                port_err_pulses=1  port_err_illegal=0  synthb_rises=0
B, WRITE trip2: class=ERROR  (same counters)   wr_hold_r=1 at the fire
```

### The three-part escape-vs-safety bar, asserted separately

- **(a) FIRES** — `class=ERROR`, `err1_rises=1`, and **`port_err_illegal == 0`**:
  every HRESP=1 pulse landed with a transfer in its data phase. The F-1
  legality property is asserted, not assumed.
- **(b) CLEARS** — measured at rest after the fire:
  `{'sub_err1_r': 0, 'sub_err2_r': 0, 'synth_b_pending': 0,
  'sub_mst_dphase_r': 0, 'sub_rd_os_r': 0, 'sub_wr_os_ctr': 0, 'wr_hold_r': 0}`.
  Explicitly asserted that `synth_b_pending` was **never** raised
  (`synthb_rises == 0`) — the TL-042 rejection mode.
- **(c) NORMAL PATH SURVIVES** — the far terminus is released and a clean peer
  **write lands byte-exact at the far side** (`landed=0xa5a50ff0`) and a clean
  peer **read returns it**. Measured for both directions.

**The write direction's `wr_hold_r` interaction, measured not assumed.** After
the write-path fire, `wr_hold_r` is still 1 (the fix deliberately adds no term
to `wr_hold_clr`). The ERROR is delivered regardless — `sub_err{1,2}_r` outrank
`wr_hold_r` in the `ahb_sub_hreadyout` mux — and the test then proves it
**self-heals**: `wr_hold_r` does not gate the address path into XHB500, so the
next write's W beat reaches s_axi and clears it. Logged:
`WRITE (c) recovered: landed=0xa5a50ff0 wr_hold_r_now=0`.

## 5. FPGA-only or netlist-affecting? **NETLIST-AFFECTING. Both lines.**

Stated explicitly, because the registry says the opposite:

- The fix is in `src/rtl/tidelink_top.sv`, which is in
  `flists/tidelink_top_full_asic_v2.flist:409` **and**
  `flists/tidelink_fpga_v2.flist`. It changes the tapeout netlist.
- It was A/B'd under **`ASIC_MIRROR=1`** (the shipping ASIC-V2 wlink error-path
  combination) and the result is the same: **HANG without it, ERROR with it**,
  with byte-identical counters. The defect is inside the `ahb_sub` wrapper and
  XHB500, neither of which differs between the ASIC and FPGA flists, so this is
  expected — but it was measured rather than argued.
- **This matters more on the ASIC than on the FPGA.** Per
  `N1_SIM_RESULT_2026_08_14.md` §6, the ASIC flist holds `WlinkGenericFCSM` 0-4
  on the recovery-**stripped** `deps` copies, so on silicon these `ahb_sub`
  backstops are the **only** recovery left on this path — and TL-037 is the hole
  in them.
- The registry's own `fix.netlist_affecting: true` is **correct**; its
  `caveats[1]` "FPGA-ONLY (PL block design). Does NOT help the ASIC" is
  **wrong** and should be replaced. The entry currently contradicts itself.
- The FPGA AXI Firewall remains worth having as a **defence in depth** — it is
  mechanism-agnostic and catches anything upstream of `tidelink_top` that this
  fix cannot reach. It is no longer the *only* option, and it is no longer a
  reason to consider TL-037 out of ASIC scope.

**Interaction with N1** (fixed at `e008c58`): the ledger's note that "the read
path's only backstop is defeated exactly where the AXI firewall is absent" is
confirmed and is now precise. N1 is the *coincident* stuck-read-plus-stuck-write
case; TL-037 is the *sequential* one — the state you are in one cycle after any
backstop, N1's included, retires a transaction it cannot actually complete. The
two fixes are independent and were regression-tested together (§4).

## 6. What is NOT done

- **`make sim_gate`** has not been run against the fix, and the new tests are
  not wired into any gate target. Both are required before it lands.
- **Not hardware-validated.** No board was touched. The obvious HW check is the
  documented 8/8 deterministic `errinject --node AW --byte 0` wedge
  (`imp/hw_gate/tl035_tl035/07_errinject_sweep.log:12-22`): with the fix, die_a
  should return a bus error and stay on the network instead of needing a
  JTAG-POR. That is a build-and-bench cycle and is not in this result.
- **No timing/area check.** One flop and one `else if` on a 2^16-cycle path, but
  it has not been through synthesis.
- The **2^16 default window** was not re-examined. ~2.6 ms at 25 MHz is a long
  time for a PS store to block even when it is bounded; whether it should be
  parameterised down for the FPGA rig is a separate decision.
- The write-direction repro shows the port issues **repeated bounded errors**
  while the wedge persists (rather than one error then normal service). That is
  survivable and is the TL-037 bar, but it is not the same as the link
  recovering — TL-009/TL-042 still own that.
