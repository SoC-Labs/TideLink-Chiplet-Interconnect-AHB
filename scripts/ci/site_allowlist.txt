# FORMAT: three TAB-separated fields.
#
#     <tracked path>	<extended regex>	<reason>
#
# All three are MANDATORY. A line missing the reason is a hard error, not a
# silent pass: an exemption nobody wrote a reason for is an exemption nobody
# is reviewing. An entry that stops matching anything is also a hard error,
# so a stale exemption cannot outlive the line it covered.
#
# THE ONLY CLASS EXEMPTED TODAY: absolute paths on the TARGET BOARD.
#
# The KR260 / PYNQ boards run a fixed vendor image in which `/home/xilinx`
# and `/home/ubuntu` are that image's own layout, reached over ssh or scp.
# They are not paths on any build host, they are not this site's filesystem
# layout, and they cannot be relocated by setting a variable here — the
# board is what it is. Each one below is already overridable by an
# environment variable where it is a default rather than a literal.
#
# NOT exempted, and deliberately so: tool installs, vendor IP roots, and any
# path under a developer's home directory on a build host. Those became
# site.env entries — see site.env.example and mk/site.mk.

# ── The checker's own test fixtures ──────────────────────────────────────────
#
# test_site_check.sh seeds a real violation of every rule and asserts the
# scanner fires on it. Those literals ARE the test: remove them and the test
# passes vacuously, which is the exact failure this whole guard exists to
# prevent. They are written into files under a mktemp directory and are never
# a path this repository resolves.
#
# Scoped to the one file, by the one pattern each case needs — not a blanket
# exemption for scripts/ci/tests/, so a REAL site path added to that file
# still fails.
scripts/ci/tests/test_site_check.sh	(printf|expect|^#     TL39=).*((/eda|/research|/apps|/home)/|-r[0-9]+p[0-9]+-[0-9]+rel[0-9]+)	Seeded violations that prove each rule fires (both classes), plus the verbatim line quoted in the header as the reason case 2 exists. They are the test's fixtures, written to a mktemp dir, never resolved by this repository.
